# Public SSR early controls: read-only implementation review

Source inspected: f77b97de76d0d838f2f03c173055b0c38c9f1785 (2026-10-06). No repository, Git, CI, API or authentication mutation was made.

## Confirmed current gap

- public-shell.tsx emits native locale/theme selects, but their cookie and navigation side effects exist only in React onChange. main.tsx dynamically imports the public SSR client, and hydrate-public-root.tsx awaits official router hydration before hydrateRoot. Therefore visible SSR controls precede those handlers.
- Theme useSyncExternalStore server snapshots are system and light. Its React effect is a second owner of html.classList. Adding only an early handler while retaining this ownership can restore the wrong class/value while hydration finishes.
- public-response.tsx already creates a fresh nonce, serializes a complete root tree separately from the outer document and puts defer assets after bootstrap/official router scripts. A fixed nonce inline script can execute in Head before the controls parse. Existing script-src allows self and nonce, never unsafe-inline/eval. html is outside the hydrated root and may safely receive theme classes there.
- canonical locale comes from URL, not NEXT_LOCALE. Existing localizePublicHref preserves query/hash, accepts only public routes, and leaves account/admin/API/external URLs unchanged. This contract must remain.

## Recommended minimum complete design

Make these two preference selectors native uncontrolled controls for their entire lifetime. Use defaultValue rather than value, and put all preference side effects in one tiny public controller. Remove the separate React cookie/assign/theme effect path. This eliminates a takeover interval entirely: one code path handles input before, during and after React hydration. It is an appropriate boundary because locale already performs full navigation and theme affects html outside the root, rather than React application state.

1. Add one dependency-free, self-contained controller module. It accepts only a theme or locale string from exact allowlists and exposes install, syncControls and dispose as a narrow public API. Its state stores the current theme independently of cookie availability. No timers, polling, MutationObserver, imported React, router, Auth or account dependencies are needed.
2. In Head, execute the fixed controller using the response nonce before styles/body. It reads only cinatoken-theme once (invalid/absent -> system), applies light/dark on html immediately, and installs exactly one document capture change listener plus one matchMedia change listener.
3. Mark the two native select elements with one fixed data-cinatoken-public-control attribute (theme/locale). The document listener accepts only HTMLSelectElement targets bearing this exact marker and contained by the current #root. It does not use closest(), generic select matching, translated labels, innerHTML or user-provided selectors.
4. Render theme defaultValue=system and locale defaultValue=location.locale, identically in SSR and client render. Do not switch a select between controlled and uncontrolled, introduce a no-op onChange, or call suppressHydrationWarning. Alter only the live select.value property during sync, never option selected attributes or React-owned children/default metadata. Existing native keyboard and labels remain.
5. After streamed #root closes, but before defer assets, call the installed controller syncControls. This restores the saved theme on the already parsed select. Optional PublicShell mount sync handles a newly mounted shell after a client route transition; it uses the controller's current state, not an old React/server snapshot. Initial locale display remains URL-derived; NEXT_LOCALE never overrides it.
6. On a theme change, synchronously update in-memory theme, safely attempt the fixed non-secret cookie write, apply html classes, and keep the select value. A failed/disabled cookie cannot turn the user's current selection back to system. System mode responds to matchMedia changes; explicit light/dark ignores them.
7. On locale change, validate en/zh/ja/ko and generate the same same-origin public path as localizePublicHref, preserving search and hash byte semantics. Only then attempt fixed NEXT_LOCALE cookie and location.assign. Do not use cookie or query-derived arbitrary return URLs. Avoid duplicate side effects by having no parallel React navigation handler. If repeated identical changes must be suppressed, suppress per processed native event or pending same-target navigation without making future different choices impossible after a canceled navigation.
8. Keep the early controller installed for the public document lifetime, rather than removing it when hydrateRoot returns (that is not a commit signal). Idempotent install prevents duplicate listeners; explicit dispose removes change/media listeners and references. If cleanup is tied to pagehide, account for BFCache by reinstalling on pageshow; do not remove permanently on persisted pagehide. Prefer page-owned listeners (automatically reclaimed when the document dies) plus explicit dispose for a deliberately unmounted root. Do not add polling or navigation timeouts solely for ownership handoff.

## Script-source maintenance

The inline script must be fixed code with no request cookie/URL/translation string interpolation. A self-contained function serialized with toString is acceptable only if every helper/allowlist is inside that function and the real built Worker/Node script is tested for free-variable/minifier failures. A small literal code string is simpler to audit, but do not maintain a divergent third locale contract: factor pure helpers where feasible or exhaustively compare emitted-script outcomes with localizePublicHref in tests. A separate blocking early JS asset is less reliable under slow network and would introduce another fetch before controls become useful.

From DOMContentLoaded is insufficient because it may await defer scripts. Observe actual SSR controls/heading while JS entry remains unserved, then use real selectOption and keyboard Arrow/Enter.
- Early light/dark/system: class and live value change immediately, cookie has the fixed value; media emulation changes class only for system. Test saved dark on fresh load, invalid cookie, and blocked cookie (current state must still work).
- Release held assets, allow the exact production React hydration to finish, assert selected value and class remain correct, no recoverable hydration/page error, no root replacement/useId drift, and another normal preference change works. No React private props/ready marker as the acceptance condition.
- Early locale for all four languages on home and a detail URL with query/hash: exact same-origin localized destination, correct html.lang, current query/hash, canonical/hreflang unchanged. Count document requests to prove one intended navigation and no unrelated private route/API request.
- Narrow scope: unmarked selects, marked nodes outside root, non-select targets, invalid locale/theme, private or external paths do not mutate cookies/navigation; no incoming credentials are serialized into HTML/script or forwarded by public SSR.
- True JavaScript-disabled browser still displays all prepared main content inline, headings/links and expected SEO/404/503. This fix does not by itself make select interactions work with all JavaScript disabled; if that is a separate requirement, add native locale links or a strictly validated same-origin preference form route rather than claim the inline runtime proves it. Do not hide/disable the early SSR controls to turn the test green.
- Existing full document/script nonce tests, exact root/useId test, locale helper tests, full Web typecheck/lint/format/unit and three-target cold Linux build remain required. Browser acceptance must bind exact candidate asset SHA; local unclean modules are insufficient.

## Important race and policy cautions

- Do not install only in main.tsx: that leaves the network/bootstrap gap intact.
- Do not remove capture listener before React's real commit, or register both early and React assign handlers: those create missing/duplicate inputs.
- Keep server snapshot data immutable if any controlled external-store variant is chosen. Reading changed cookies as getServerSnapshot during client hydration would differ from SSR and violate React's hydration contract. A controlled alternative needs a genuine commit handoff and deduplication and is larger than native single ownership.
- Maintain no-store HTML, strict nonce script policy, anonymous catalog boundary, no request Cookie/Authorization leakage, trusted canonical origin, same-origin form-action, and original cancellation assertions. No authentication grant is needed for this public fix.

Primary React references checked: https://react.dev/reference/react-dom/client/hydrateRoot ; https://react.dev/reference/react/useSyncExternalStore ; https://react.dev/reference/react-dom/components/select . Their documented constraints support identical initial SSR output, matching server snapshot during hydration, and a stable controlled/uncontrolled choice. Actual production browser behavior still needs the network-held candidate acceptance above.
