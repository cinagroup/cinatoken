## 主机链路

新增 `scripts/deploy/byok-d1-case-dispatch.mjs`，只按既定顺序发送十个用例，不接受自定义 origin、路径、SQL 或任意用例 ID。验证初始控制记录、令牌摘要及日志 run 身份；每次请求必须先在固定排他日志刷盘 PENDING，严格确认回执后才 ACK 和推进游标。对外返回副本，调用者不能通过修改返回值污染后续内部校验。

仅固定 staging origin 接收凭据，禁止重定向；POST 无正文，附带正确 case/stop 命令。响应最多 8 KiB、最多 256 次读取、最长等待 30 秒，要求严格 UTF-8 JSON、Content-Type、no-store、声明长度与实际字节一致。成功回执复用原持久控制记录解析器，核对用例顺序、PASS、嵌套字段/计数界限和 `midBatchWallClockExpiryVerified=false`；不存在“本地成功推断原生中途到期通过”。主机 HTTP 确认不能代替操作器随后独立读取 D1 对账。

任何已消费步骤的网络错误、非 200、畸形回执、读取超时、取消或 ACK 刷盘失败都停止后续用例；即使远端还未认领、控制行仍 ready，也不重发。迟到响应只回收，不把失败改为成功。主机超时/AbortController 不证明远端 SQL 已取消。

原日志增加不可变公开身份，以及两个仅用于收尾的步骤：`stop`、`seal-fence`。它们在未知结果后仍各允许尝试一次，与关闭入口/Access、撤销令牌一致；不允许重开围栏、重置许可、删除未知样本或让已污染日志恢复普通流程。STOP 与在途用例可以并存；失败后仍可封闭围栏，清理仍被禁止。同一日志只要已经尝试 STOP 或封闭围栏，新建发送器对象也不能再发用例。尚未提供自动 seal 的云管理适配器，测试中使用固定围栏 SQL 对 SQLite 执行。

## 云端只读观察边界

本轮使用 Cloudflare 技能约束固定资源、只读 SELECT、凭据不落盘和默认禁止写入；Firecrawl CLI 不可用，文档回退到官方网页。[D1 REST API](https://developers.cloudflare.com/api/resources/d1/subresources/database/methods/query/)确认 batch 请求形状；[D1 limits](https://developers.cloudflare.com/d1/platform/limits/)仍区分 Free/Paid 每次调用预算，因此可见零账单不能替代实际套餐核验。未采用本地参考文件不可靠的 session timeout/close 示例。

最初的沙箱尝试在 D1 身份 GET 失败，无 HTTP 状态、无数据库读写。随后两轮网络获准的只读复核各有 29 个完整 ACK，D1 各读取 674 行/写入 0 行；四台 staging 版本/设置、已知入口关闭、Access deny-all、schema/56 表计数、旧 token/tail 缺席及三台生产 settings 在首轮检查匹配。两轮均在网关代码下载 HTTP 200 后正文超时，没有通过完整复核，不能把 HTTP 200 当作完整代码摘要验证。

定向无压缩诊断在 60 秒内收到 3,276,236 字节，已知网关模块为 3,834,544 字节，尚未完整 EOF；这与传输偏慢相容，不证明云端代码改变。独立可见账单读取有 105 行 Workers/D1 记录，截至 2026-09-20T00:00:00Z，ContractedCost/CumulatedContractedCost 均为 USD 0；仍不是最终增量账单或实际剩余余额。

另建只读观察脚本，仅对固定网关代码 GET 放宽为 120 秒、正文仍限 12 MiB，其余传输边界不变；未修改共享管理传输、产品或真实用例的超时。全部尝试独立留证，结果不覆盖早先失败。最终结果与汇总计数在同名机器清单中逐项校验。
