# C04 v376 buyer COMMIT response loss

2026-09-25. **Review only; default off.** The [v376 application protocol](../../../../packages/core/src/db/postgres/legacy-buyer-commit-ack-v376.ts) calls the existing narrow [v372 buyer writer](../../../../packages/core/src/db/postgres/critical-writes.impl.ts) exactly once. If the writer rejects, it creates a new dedicated [v375 terminal reader](../../../../packages/core/src/db/postgres/legacy-buyer-terminal-reader-v375.ts) connection, compares the pre-write expected financial facts, closes that reader, and returns `confirmed`, `unconfirmed`, `conflict`, or `reader_error` with the original write error. None of these paths invokes the writer again. The wrapper snapshots the full expected structure, including nested attempt facts, before invoking the writer; a caller mutation while COMMIT is pending cannot change the readback target.

The [native fixture](../../../../scripts/db/cutover/postgres-legacy-buyer-commit-ack-v376.native.test.mjs) passed **17/17 stages with cleanup PASS** on local PostgreSQL 18.6; see its [machine report](./C04-legacy-buyer-commit-ack-v376-report.json). It installs formal PG73 and the review-only v368/v371/v372/v375 plus v2 economic and ordinary-admission proposals in an owned cluster. A transparent [PostgreSQL wire proxy](../../../../packages/core/src/test-support/postgres-commit-ack-proxy.mjs) forwards one real writer `COMMIT` to PostgreSQL, then suppresses the server's `CommandComplete(COMMIT)` and closes the writer connection before that command response and `ReadyForQuery` reach postgres.js. The writer reports `CONNECTION_CLOSED`. A newly opened terminal-reader LOGIN on a different backend confirms the committed log, v2 event, xid8 producer marker, matching buyer budget receipt, settled holds, and one debit. The proxy does not manipulate TCP ACK packets; the result proves loss of the PostgreSQL COMMIT command response at this local intermediary.

The fixture also shows the non-replay decisions: a late audit failure rolls back and reads `unconfirmed`; a committed old buyer log without the economic receipts yields `conflict`; a privileged local deletion of the budget receipt makes an otherwise committed request `unconfirmed`. A direct second call to the v372 writer is rejected without a second debit. While the writer is pending, the fixture changes the caller's expected amount and nested evidence hash; the wrapper still reads against its original snapshot.

**Activation remains blocked.** The v375 financial read does not bind model, route target, origin, protocol, or the complete Provider request/response to a durable pre-send intent. The fixture changes model, route target and origin in the supplied request while leaving v375's expectation identical; the reader still returns `confirmed` even though the committed buyer log stores the original values. The result also cannot independently prove Guardrail rows, unreserved windows, audit and daily statistics came from that same transaction: those side effects lack their own request-scoped transaction marker. Buyer amount and usage remain caller supplied, without authenticated final Provider billing. The wrapper relies on the caller to provide a genuinely new dedicated LOGIN after writer failure: its TypeScript check covers the PostgreSQL driver, and the v375 SQL checks `SESSION_USER`, but the wrapper itself cannot verify connection freshness or backend identity. The fixture proves separate backends and the reader ACL only for this run. The production factory and credential wiring do not exist. No formal migration, remote SQL, Worker or Provider was changed.
