## 1. 本轮结论

只执行一次合成推理。其后的 8 次有界 WebSocket Upgrade 均收到原始完整 canonical 409，且每次诊断头均证明观察请求落到与原推理不同的逻辑实例；不是同实例 eligible epoch 不匹配。本轮没有匹配观察连接、容量帧或 stage marker，不能证明原实例容量释放，也不能证明 isolate 被回收。

8 次诊断均在下一次发现前持久化，原拒绝正文、摘要、时钟和 primary 身份逐项核对，8 条 classification 全为 `instance_mismatch`。发现过程耗时 12,073 ms，未增加原 8 次 / 20 秒上限。不同 UUID 只代表不同逻辑实例，不代表 8 台物理服务器、8 个地区或原实例已消失。

Cloudflare 明确不保证两个用户请求被路由到同一个 Worker 实例。因此后续不能以增加独立观察请求次数作为可靠的同实例验收方案。[官方分布式执行说明](https://developers.cloudflare.com/workers/reference/how-workers-works/)

## 3. 原生与账务证据的独立边界

原始平台 tail 证明同版本、同请求的 `native-wait-until-task-cancellation`，客户端取消顺序由同一操作器单调时钟核对。这证明请求任务的原生取消，不证明整个 isolate 终止。

原 finalizer 只调用一次恢复 RPC，PENDING → ACK，`committed=1`、`unknown=0`。六组财务表各一条事实，成功日志的合成单图费用为 0.1、预算扣减 100,000 micros，真实模型支出仍为 0。raw_usage 保留 text_tokens=3、image_output_tokens=7，而图片按张计费的文本计费列为 0；原上游尝试次数为 1。没有第二次去重 RPC，也不把历史幂等证据冒称本轮重测。

已确认的“有效 completed 图片 + 上游 DONE 为不可逆成功结算点”保持不变；账务恢复成功不能替代同实例容量释放证据。本轮不改变生产结算算法，不以 TTL 或取消事件提前释放未知容量。
