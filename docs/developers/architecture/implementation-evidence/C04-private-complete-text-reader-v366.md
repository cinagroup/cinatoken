# C04 private complete text route reader v366 (review only)

2026-09-25. This proposal gives an independent holder database principal a bounded read of one selected route from an **already committed v360 strict platform flat-text quote**. The read occurs before v362 grant issuance. It does not reserve funds, authorize a send, or bypass the v362 grant's later full-manifest and live-source checks.

## Authority and data boundary

- [`complete-text-private-route-reader-v366.sql`](../../../../packages/core/migrations-proposals/postgres/complete-text-private-route-reader-v366.sql) is outside formal PG73. It requires a separately provisioned direct `NOINHERIT LOGIN cinatoken_gateway_complete_text_private_reader` with no memberships, base-table rights or prior gateway function rights. Installation is an explicit migrator transaction using `cinatoken.complete_text_private_route_reader_activation=reviewed-v1`. The role is distinct from ingress planner, v362 granter and v365 send holder.
- The sole grant is `read_private_complete_text_route_v366(request_id, quote_id, candidate_index, route_target_id)`. The function checks `SESSION_USER`, read-committed isolation, request/quote selection, capability/key/user/workspace state, quote expiry, active BYOK exclusion, selected immutable manifest hashes, Provider ciphertext hash, active route/pool/Provider/verified endpoint/link, and exact v359 generation/subject attestation. It bounds route ID, Provider ciphertext and endpoint map bytes. Source tables are locked through the read transaction; they can change after it commits, so the later v362 grant remains mandatory.
- Success returns only `status`, `quote`, and `selected`. `selected` includes the holder's stored `enc:v2:` ciphertext, selected OpenAI endpoint configuration, Provider/route identity, verified endpoint row, and source digests. Other Provider protocol endpoint maps are omitted. Failure returns only a status. The public runtime and ingress planner have no EXECUTE right; the private reader has no direct `SELECT` on Provider, quote or manifest tables and cannot `SET ROLE` to the migrator/runtime.
- [`postgres-private-complete-text-reader-v366.ts`](../../../../packages/proxy/src/services/postgres-private-complete-text-reader-v366.ts) creates a one-shot direct-login connection, validates the SQL result and maps it to the existing v365 holder's three read ports from **one** committed snapshot. It waits for the transaction and connection-close acknowledgement. A substituted runtime LOGIN, malformed result, SQL denial or unknown close acknowledgement fails closed. This adapter is default-unwired and must live only in the private holder Worker.

## Activation gaps

The current public Proxy still has broad Provider `SELECT`, the shared software KEK and its own outbound fetch path. This local proposal does not establish a separate Provider KEK/KMS unwrap policy, rewrap or rotate stored `enc:v2:` credentials, split Proxy/Admin database identities, configure real Worker bindings, or drain the old sender. The v366 reader uses the existing ciphertext format because the v360/v362 manifest contract requires it. A distinct credential domain cannot be proven locally from this fixture and remains an activation blocker.

The v366 read can become stale immediately after its transaction. The v362 grant must be issued afterward under its distinct LOGIN and must reject any route, ciphertext, attestation or identity drift before v365 custody/send-start and physical fetch. A full native read→mutation→grant→zero-fetch Worker fixture, plus result lifecycle, lease renewal, reaper fences and economic settlement, remains required for C04 acceptance. No remote SQL, deployment or Provider call was made.
