## 接口发现

依照 Cloudflare 技能先核对公开契约、已安装 SDK / Wrangler 源码，再用有界管理 GET 检查真实响应。Firecrawl 获取的官方[Pages 绑定文档](https://developers.cloudflare.com/pages/functions/bindings/)说明绑定配置和重新部署步骤，但没有解决历史响应缺省字段的含义。已安装 SDK 的历史 Deployment 模型同样缺少这些绑定字段。

以当前 staging Worker settings 为阳性对照：返回 200。对 Pages 项目返回的 production 内部 Worker 名称，settings 也返回 200 且包含显式 bindings；services 接口返回 404 / 10090。随后确认两个环境的 versions 列表与版本详情均可读。因此，services 返回 404 不能被解释为 Pages 内部 Worker 的配置与版本不可读，更不能代替其他接口的实际检查。

三组探测共 **10 次 GET，9 个 200 / 1 个 404**。只保留字段结构、非敏感标识与摘要，没有输出环境变量或凭据值。初始详情探测用项目名称构造域名，未采用 API 返回的实际 subdomain，因此其 URL 不匹配结果不能证明没有关联；正式收集器已使用实际 subdomain。

## 收集器与本地验证

新增 `scripts/deploy/byok-d1-pages-worker-versions.mjs`。遍历所有可见项目的 production / preview 内部名称，不按当前 `uses_functions` 或版本预览标志筛除；每个可列版本读取自身 resources.bindings，并复核前后版本目录与项目目录。

保留 1000 GET、4 并发、总计 10 分钟、单请求 20 秒和 2 MiB 正文限制。验证分页、重复 ID / 内部名称、归属、版本号、绑定别名、正文及目录漂移。每个项目最多两个名称、每个名称最多 500 版本。仅版本目录第一页允许记录一个结构有效的 404，状态为 `NOT_FOUND_UNVERIFIED`；第二页或已知版本详情的 404、403、错误结构均停止。404 的含义必须保留未知，不能当成空版本列表。

结果单次保留、请求前刷盘、无自动重试；普通变量值只参与摘要，不保存正文。`CF_PAGES_URL` 仅提取与 API subdomain 匹配的八位前缀候选，不把普通绑定值升级为权威部署身份。

**276 PASS / 0 FAIL**：新源码 43、打包 43、既有 Pages 历史清点 54、Worker 版本清点 47、当前配置清点 37、读取传输 52。覆盖旧版本绑定、404 与空集合的区分、404 漂移 / 非第一页 404、错误字段与重复项、实际子域名、取消 / 超时 / 迟到响应、现有保留目录、符号链接及 1000 请求上限。这是主机测试，不是原生 Workers / D1 验收。
