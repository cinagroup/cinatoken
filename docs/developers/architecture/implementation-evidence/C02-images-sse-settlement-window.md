# C02 — Images SSE 成功结算点与耐久交接

2026-09-08；Checklist v1.88。状态：LOCAL_PASS，未部署，C02.G 不关闭。

用户明确批准：网关验证有效 completed 图片及上游 DONE 后，成功结算不可逆；之后客户端取消不撤销费用。仅 completed、没有上游 DONE 的情形保留原规则。此授权是收费边界决策，不扩大云资源或费用授权。

## 修复前实证

真实共同 Worker handler / Images 路由 / driver，配合本地 SQLite 完整迁移及三个恢复草案、私有合成 transport；不是线上 Workers，也没有付费模型。

| 时序 / 故障 | 修复前观察 |
| --- | --- |
| 读到 completed + DONE 后立即取消或 abort | 错误日志、0 费用 |
| 同样读到 DONE，晚一个事件循环取消 | 成功日志、0.1 合成美元 |
| 账务日志提交前失败 | 客户端成功流；无日志，预算消费 100,000 micros，无恢复快照 |
| 提交前暂停 | 客户端已读完成功流，数据库仍为 dispatched 预留 |
| 提交后丢确认 | 已有读回确认路径识别成功，未重复收费 |

14 项严格基线观察通过，但它们证明缺口，绝非产品验收通过。初始观察测试和首次加强断言时的 metadata 层级错误、两个新延迟取消预期错误均已记录；修复前源码另存归档，不覆盖旧证据。

## 当前实现

driver 在终态形成时锁定结算结果，而非等待下游最后一次 pull/EOF。有效 completed、数量/用量校验及真正上游 DONE 才能成功；协议错误合成的 DONE 保持错误结果。已锁定的成功不受后续取消影响。

公开路由增加有界交付门：只处理内部 driver 已验证的完整帧，不缓存整个响应。下游 DONE 等待账务提交确认；交付等待最多 15 秒。未确认时输出带可信 request_id、outcome_unknown、retry_safe=false 的结算错误再结束；15 秒是交付等待上限，不撤销正在持久化的金融事件。客户端取消不等待数据库、不发起第二次模型请求。

耐久恢复通过服务端 `imageUsageRecovery: { settlementLeaseSeconds: 30, streaming: true }` 显式启用；默认不自动扩展旧部署配置。启用时先记录/认领出站意图，再持久化脱敏用量快照和原子恢复任务，确认接受后才放行 DONE；后台快速结算仅持有引用。快照已接受但提交前失败可由既有带租约消费者补账，重复恢复不重复扣款。streamed 身份绑定到请求 scope；普通请求不能注入 SSE 快照，流请求收到非 SSE 错误仍能持久化错误事实。

仅启用普通 Images 恢复的旧组合仍保留独立 SSE 路径，但新交付门要求实际账务提交后才能交付成功 DONE。该兼容路径的提交失败仍可能保守消费预留且没有恢复快照；现在不会向客户端伪装成无错误的成功流。不能把它当成完整耐久恢复方案上线。
