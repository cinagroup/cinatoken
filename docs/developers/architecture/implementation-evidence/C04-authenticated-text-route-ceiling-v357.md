# C04 DB-derived text route ceiling fragment (v357)

2026-09-25. **Review-only local proposal.** The [v357 SQL](../../../../packages/core/migrations-proposals/postgres/authenticated-text-route-ceiling-issuer-v357.sql) follows the [v356 bearer capability](./C04-authenticated-quote-db-boundary-v356.md). It is a narrow price fact for one flat-text route. It is **not** a complete request quote and grants no budget hold, dispatch, or settlement.

## Contract proved locally

A third direct `NOINHERIT` LOGIN, `cinatoken_gateway_request_route_ceiling_issuer`, has only `EXECUTE` on the v357 issuer. It presents the unguessable v356 capability, request ID, body digest, and one route target ID. The v357 function locks and checks the v356 capability and current Key/user/personal Workspace, including status, ownership, expiry, and epochs. A successful call creates one insert-only row and atomically marks the v356 capability claimed. No argument can supply a budget amount, buyer factor, tariff JSON, or settlement basis. A failed route/pricing check leaves the capability unclaimed.

The function accepts only an active OpenAI Chat passthrough route in an active default pool, with no shared-channel flag, route override, or custom parameters; the user must have no custom charged factor. The target must link to a status-verified, unexpired Endpoint for the same model and provider and carry a structurally valid persisted route subject fingerprint. The Endpoint must have an explicit USD currency and flat text prices with non-negative fixed decimal `prompt`, `completion`, optional cache rates, and optional request cost; discount must be absent or zero. Other metered dimensions fail closed. The function copies the relevant route/Endpoint source fields, persisted fingerprint, and their SHA-256 digest into the insert-only fragment. The absence of a shared-channel flag does not prove which provider credential a later dispatch will use.

For this subset, SQL calculates a per-attempt ceiling using `max(context_length, max_prompt_tokens)` for input and `max(context_length, max_completion_tokens)` for output: `ceil(1,000,000 × [input_capacity × max(prompt, cache rates) + output_capacity × completion + request])`, plus one micro for nonzero cost to cover intermediate six-decimal rounding. The fixed three-attempt ceiling is exactly three times that number, with checked JavaScript-safe integer bounds. A zero amount is issued only when the persisted applicable rates derive zero. This is a bound for the declared text-token capacities and selected target; it is not evidence that the complete Chat fallback plan or all provider billing behavior fits the subset.

Its [JSON report](./C04-authenticated-text-route-ceiling-v357-report.json) is **PASS, cleanup PASS, 13/13 stages**. It proves default-off and contaminated-role refusal, direct-role ACLs, wrong capability/body rejection, missing route fingerprint refusal, exact one-shot consumption, a DB-derived `17,001` micro per-attempt and `51,003` micro three-attempt example, increased ceilings when declared prompt/completion capacities exceed context, immutable copied source after live price mutation, factor/override/multimedia and missing/null currency refusal, derived zero for free persisted USD prices, Key revoke/reactivate invalidation, expired Endpoint refusal, no numeric issuer arguments, and the legacy broad-runtime-grant interlock. ## Exact remaining boundary

The v356 body digest is caller asserted; SQL does not reconstruct the HTTP bytes. The target ID is caller selected; SQL cannot prove it is the full eligible fallback plan. Chat routing also depends on request fallback models, provider preferences, surfaces, policies, performance and availability filters, private BYOK and shared seller credentials, and mutable route/Endpoint/User rows. The persisted route subject fingerprint is present but SQL does not recompute it from the current decrypted credential and normalized provider endpoint; it can be stale after a route or provider edit. The v357 snapshot has no monotonic source revision, so an ABA change can restore the same source hash. A future grant must check the fresh subject and current state or an independently maintained version, quote coverage of every eligible attempt, actual credential identity and billing basis, and a committed full-plan hold before any fetch. This fragment's amount must never be passed as a supposedly complete quote to v350/v351.

C04.1 also requires buyer and seller/upstream prices, commission, currency/unit, entitlement version, credential owner, billing mode, and effective-time snapshot. The fragment records USD text buyer price inputs only and does not satisfy that contract. Shared-Key seller quote versions are separate seller facts; nonshared supplier cost may remain unknown. No production role or Worker/Hyperdrive wiring, formal migration, remote test, D1/MySQL parity, complete quote issuer, budget consumption, dispatch grant, buyer critical write, or physical egress binding is changed here. A retention policy for insert-only fragments and their referenced v356 capability rows is still needed. C04.1–8/G remain open.
