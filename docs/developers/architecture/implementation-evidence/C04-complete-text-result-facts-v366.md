# C04 v366 review-only result facts after send start

2026-09-25. [The v366 SQL proposal](../../../../packages/core/migrations-proposals/postgres/complete-text-result-facts-v366.sql) appends bounded facts to a v362 immutable `unknown` grant and the v365 holder custody/send-start records. It is default off, is not a formal migration, and has not been deployed or called against a remote database or provider.

## Authority and fact contract

The existing direct `NOINHERIT` holder LOGIN can call `append_complete_text_holder_fact_v366`; a newly provisioned, separately authenticated direct `NOINHERIT` provider-bill LOGIN can call only `append_complete_text_provider_bill_v366`. Neither LOGIN can read or write the fact or conflict tables directly, invoke the other writer, or call the private common writer. `SESSION_USER`, `READ COMMITTED`, and the current server transaction are checked inside the functions. The SQL installation requires a migrator session, the reviewed activation setting, formal PG73 migration identity, v362/v365 dependencies, table ownership, role isolation, and no prior v366 objects. It rejects a bill role with table or economic-schema access.

Each fact records the exact `grant_id`, request/quote, holder run, lease epoch, and, for every sent or billed kind, the unique v365 send-start ID. It copies the frozen grant claim, final body, route, provider, endpoint, credential class/ID and ciphertext fingerprint, outbound body and URL **hashes** from the stored grant; callers cannot supply these values. It stores no bearer, Provider ciphertext, raw upload, or URL. The database computes SHA-256 over PostgreSQL's canonical `jsonb::text` representation and requires an identical caller digest. Evidence is limited to a JSON object of at most 1024 UTF-8 bytes with exact typed keys for each kind. `received_at` is server time.

The holder kinds are `no_fetch_attestation`, `fetch_invoked`, `transport_unknown`, `provider_usage`, and `provider_zero_charge_observation`. Only `no_fetch_attestation` may be written before a send-start marker. Its pre-start presence **does not** fence the holder or prevent v365 from starting later. `provider_zero_charge_observation` is deliberately named as a holder observation and can never, by kind alone, establish an authoritative zero charge. The independent bill role writes `provider_bill` with a bounded provider request reference, event ID, USD amount (including zero or an amount above the reserved ceiling), and bill-document digest. A unique `(frozen provider_id, provider_event_id)` key rejects duplication under a different nonce or grant for the same provider while allowing distinct providers to use the same event ID. If a bill arrives without a start marker, this writer rejects it; an external incident intake must preserve such evidence for investigation.

`(grant_id, evidence_nonce)` is unique. An identical nonce, source, kind, digest and bound run/start returns `already_recorded` with the existing fact ID. A conflicting nonce returns `evidence_nonce_conflict` and appends a digest-only, deduplicated audit row. Neither response creates fresh send authority. A second bill with an existing event ID from the same frozen provider returns `provider_event_conflict`; a simultaneous cross-request race is also stopped by the provider-scoped unique index. Caller validation, evidence provenance and event correlation still belong to the independent bill adapter. HTTP status, transport failure, missing usage, and a holder zero-charge observation never imply zero billing.
