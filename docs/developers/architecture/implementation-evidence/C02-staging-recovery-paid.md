## 实现与样本边界

新增 [合成样本工具](../../../../packages/proxy/scripts/staging/usage-recovery-paid-fixture.mjs) 和 [7 项测试](../../../../packages/proxy/scripts/staging/usage-recovery-paid-fixture.test.mjs)，接入 Proxy 的常规 staging 回归链。未修改任何 Worker 运行时、SQL schema、财务算法或发布配置；本轮没有部署。

工具在本地真实 SQLite 中调用既有意图、预留和结算快照仓库，捕获其实际 INSERT / UPDATE 及参数，再通过 staging D1 的 batch 查询接口执行 18 条种子语句。不直接复制终态行：预留 INSERT 必须从 reserved 开始，并由触发器维护预留计数；任务也由不可变快照的真实触发器创建。不会手写已完成任务、账务日志或提交回执。[D1 batch 查询接口](https://developers.cloudflare.com/api/resources/d1/subresources/database/methods/query/)

每轮生成独立 UUID 用户、Workspace、API key、3 个请求和独占模型统计标识。预检确认这些标识全部不存在，恢复四表为空；只有这三个样本可供消费者扫描。用户与 key 在种子 batch 结束时均为 disabled；没有创建任何有效上游凭据、真实模型或模型路由。

## 失败记录、本地覆盖与清理

第一次操作在写入前失败：操作脚本的 schema 查询适配层只返回 results，遗漏检查器要求的 success。27 次管理请求、2 次只读 schema 查询、638 行读取、0 写入；没有创建令牌、开放入口或写入样本。最后只读复核也因同一适配错误失败，保留原记录。修正适配层并补成功 / 缺 success / success=false / 传输失败测试后，第二次完整执行通过；没有放宽运行时 schema 核验。

本地 7 项专项通过；控制、host、专项组合 118 项通过；staging 定向 TypeScript 检查通过。专项包含：真实仓库种子往返；重复种子原子拒绝；费用审计 INSERT 失败时整批预算/回执/任务/日志/统计回滚；提交成功但确认丢失后读取回执对账；重复执行；精确清理保留另一租户完整记录；证据检查器拒绝金额、日期、统计次数、摘要、回执版本、任务次数或审计缺失。**故障注入与确认丢失这两类证明仍仅本地 SQLite，不宣称已经在 Workers 上完成。** 完整 staging 链 **35 + 7 + 130 + 39 + 65 + 83 + 24 = 383** 全部通过，最后 24 项进程退出 suite 等待至终端退出码 0。因终端输出截断，前四组另行重跑并保存完整计数，不从截断日志猜测。完整 Core 类型检查未重跑，历史 32 条诊断保留。

最终关闭控制入口 → 禁用令牌 → 关闭 service-auth 401 模式 → 恢复 deny-all → 删除令牌并回读。入口关闭、专用策略拒绝、无 leased 样本后，再执行仅针对本轮请求 UUID / 用户 / 独占模型标识的清理。删除了本轮合成账户、预留、快照、恢复任务、回执、日志、审计和统计；生成参数及核验结果保留在证据中，可重新构造合成样本，不是删除真实资金记录。

收尾确认四个 staging Worker 的 workers.dev / previews 关闭，临时令牌不存在，其他 Access 应用与生产三个配置指纹未变，控制和接收端配置/版本未变。24 个恢复 schema 对象定义核验通过，56 张表行计数回到基线，本轮 11 组 scoped 查询全部为空。没有重放 ALTER、回滚全库或广泛删除共享数据。
