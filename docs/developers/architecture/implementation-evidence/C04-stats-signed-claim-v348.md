# C04.7 signed seller statistics claim primitive (v348, review only)

The [v346 authorization boundary](./C04-postgres-stats-auth-boundary-v346.md) showed that the ordinary SQL runtime can forge a portal session for another seller and can set an arbitrary seller GUC. The [v348 proposal](../../../../packages/core/migrations-proposals/postgres/shared-key-stats-signed-claim-v348.sql) supplies a narrower database verification primitive for a claim issued by a separately trusted authority. It creates a dedicated direct `cinatoken_gateway_stats_reader` LOGIN contract, a migrator-owned private schema, an HMAC-SHA256 key table, and a used-nonce table. The issuer signs `v1|stats.read|key_id|seller_id|sorted_key_ids|expiry_epoch|nonce`; IDs exclude delimiters, scope IDs are unique and sorted, and expiry is at most five minutes ahead. A revoked or inactive key, altered seller/scope/audience, duplicate nonce, or wrong signature fails closed. The reader can execute the verifier but cannot read its signing material or nonce table. The ordinary runtime cannot execute the verifier or switch to the reader role.

The installer is default off: the direct migrator must set `cinatoken.shared_key_stats_claim_install='reviewed-v1'` locally in its transaction after exact formal PG73. It rejects any reader role membership, existing `pgcrypto` placement, or a preexisting claim schema. Its lock and statement limits, ownership, ACL, and function security checks are in the SQL. `pgcrypto` lives in the private schema. [PostgreSQL 18 pgcrypto](https://www.postgresql.org/docs/18/pgcrypto.html) supplies `hmac`; [PostgreSQL extension documentation](https://www.postgresql.org/docs/18/contrib.html) describes trusted extension installation, and [CREATE FUNCTION security guidance](https://www.postgresql.org/docs/18/sql-createfunction.html) calls for a safe `SECURITY DEFINER` search path and controlled `EXECUTE` grants.

The [owned PG18.6 native fixture](../../../../scripts/db/cutover/postgres-shared-key-stats-signed-claim-v348.native.test.mjs) installs formal PG73, invokes the real broad runtime-grant script, and creates distinct migrator, ordinary runtime, and stats-reader password sessions. A Node signer independent of those SQL sessions issues synthetic claims. It tests canonical seller/key scope, committed replay including two concurrent reader sessions, explicit rollback reuse, tampering, expiry, audience, key revocation, private table ACL, and grant rerun. The [machine result](./C04-stats-signed-claim-v348-results.json) pins the formal corpus, SQL proposal, fixture, and real grant-script SHA-256 values and records local cleanup. The fixture is registered in [the native CI workflow](../../../../.github/workflows/proxy-dispatch-safety.yml); Linux CI has not run in this workspace.

This is a verifier primitive, not a statistics reader. The direct LOGIN has no read permission on the credited-usage projection. The subsequent [v349 binding proposal](./C04-stats-claim-reader-v349.md) calls the verifier and projects current seller-owned keys in one transaction; Admin seller or all-seller permission and HTTP route binding still need separate work. Nonce uniqueness is durable only after its transaction commits: a caller that reads and explicitly rolls back can reuse the claim until expiry. The independent production issuer, secret provisioning and rotation, nonce retention policy, production `pgcrypto` availability, application binding, target-scale full-history readiness audit, and lock/latency evidence remain open. No formal migration, production grant, remote SQL, or deployment changed; `SHARED_KEY_CREDITED_USAGE_READER` stays disabled and C04.7 stays unchecked.
