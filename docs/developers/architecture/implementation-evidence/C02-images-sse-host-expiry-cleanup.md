## 清理规则

新模块仅处理规范合成身份、最多两个不同模式的请求，不进入生产账务路径。

| 保留的真实探针状态 | 删除前必须满足 | 实验结果 |
| --- | --- | --- |
| held-before-insert | 原始取消观察与自有 held 值完全一致，匹配原生平台证据；只有 intent 和 dispatched 预留，没有快照/任务/回执/日志 | 仅本次平台取消条件可通过；客户未知结算政策仍未完成 |
| held-after-insert | 同上，另有原生成功元数据；快照/任务已经由唯一回执结算，完整财务校验通过 | 本次平台取消条件可通过；不证明 isolate 回收 |
| host-expiry-not-observed | 所有者及请求/快照身份一致；写入前仍是 intent-only，写入后必须已经完成结算；允许没有取消事件的自有 armed 观察行 | 只允许失败实验收尾，experimentPassed=false |

未恢复 pending job、缺失 held 平台证据、release-requested、身份或金额异常、非 terminal 上游均拒绝删除。不会把 held 改写为 release-timeout，不构造假用量、退款或回执，也不重发推理。清理删除的是合成测试对象，不是客户自动对账功能。

## 原子性与顺序

先核验/关闭网关 Access、确认固定 staging D1、撤销合成 API key，再检查原有固定 350 秒安全窗口。完整线上操作器仍需独立关闭控制端 Access、处理临时 token/tail，并结合恢复调用的持有窗口；本模块不隐含这些外部职责已完成。

读取六组完整财务行、快照探针、取消观察、上游探针及所有者；先保存未经改写的证据，再把数量守卫、所有已观测字段的平衡表达式守卫与全部删除放进同一 batch。日志改为 SELECT *，非计价字段变化也会阻止删除。账户 spent/reserved 必须与已结算/intent-only 数量精确对应。

沿用有界批次预算：最多 256 条语句、每句 100 参数、单句 100 KB、整体传输 1 MiB；不能为适配传输而拆事务。Cloudflare 技能促使核对当前官方文档：D1 batch 中某句失败会回滚整个序列，因此守卫和删除必须同批执行。[D1 batch 官方说明](https://developers.cloudflare.com/d1/worker-api/d1-database/#batch)。这些是本工具的保守预算，不是所有账户的平台配额声明。

删除确认丢失后，重入路径只确认所有相关行及命名夹具均不存在；不会重复结算，也不会根据空库状态补写实验通过结论。保存失败、数据库状态变化或后半段删除失败均保留财务数据。

## 本地证据与限制

新增 25 项测试，使用实际网关、原生 SQLite 事务、现有结算与独立恢复代码；覆盖两个请求的 intent-only/committed 混合运行、两种模式的 held/计时器存活/未取消分支、十类证据拒绝，以及保存失败、快照/取消/非计价日志字段变化、晚到额外行、整批回滚、删除 ACK 丢失。所有正向清理均复原数据库计数，并验证另一无关租户的行完全不变。

held 状态用本地“标记已提交但确认丢失”的注入构造，tail 和上游终态是明确标注的合成夹具；没有改写真实探针 phase。这验证清理合同，**不是原生 Workers 取消或整个 isolate 回收证据**。待恢复负向样本还显式阻断确认读取，并断言真实 pending job 且没有回执/日志，避免因生产者自行确认而误测。

首次 23 项测试为 5 通过、18 失败，原因是测试错误期待生产者确认成功后的恢复调用仍新增一次提交。修正为暂停期间独立恢复、生产者结束后再次零提交，未改变运行时代码；随后 23/23 及新增混合运行后的 25/25 通过。完整回归见 [机器证据](C02-images-sse-host-expiry-cleanup-results.json)。Node 22 与远程 CI 尚未执行。
