# C04.7 credited-usage reader gate and response adapter (v344, review only)

The [reader proposal](../../../../packages/core/migrations-proposals/postgres/shared-key-credited-usage-reader.sql) depends on the private [contribution store](../../../../packages/core/migrations-proposals/postgres/shared-key-credited-usage-store.sql). It installs an owner-only reader and a separate activation gate. The gate stays absent until both source cursors are complete and a `REPEATABLE READ` full-history audit verifies each legacy/economic credit against its immutable contribution and each seller/key summary against those contributions. Source triggers capture later concurrent inserts in the source transaction. The function checks that seven credit/immutability guards remain enabled on every read. `pending_manual` rows do not contribute to credited totals.

The read function requires an explicit seller ID and joins the current `shared_keys.seller_user_id` to the immutable seller-snapshot summary. After a reviewed owner transfer, historical credits stay with the former seller. A new owner sees zero until their own credits arrive. The existing legacy-only rebuild can still overwrite `shared_keys` fields; [the response adapter](../../../../packages/admin/lib/shared-key-credited-usage-reader.ts) reads the private summary at the seller/admin list boundary without changing the legacy writer's CAS snapshot. The seller route supplies the authenticated `principal.userId` and refuses repository rows outside that seller. The admin route groups keys by their current seller. Both routes require the exact `SHARED_KEY_CREDITED_USAGE_READER=reviewed-v1` binding, which is absent by default. The adapter rejects a missing row, owner drift, invalid numbers, or an unavailable database gate rather than returning mixed old/new statistics.

**Runtime access remains blocked.** The shared `cinatoken_gateway_runtime` LOGIN can choose any SQL function argument; a seller argument alone cannot prove the requesting end user's identity. The proposal therefore grants no runtime `EXECUTE` or private schema `USAGE` on the reader. The function lives in `cinatoken_shared_stats`, outside the broad `cinatoken_gateway` function grant performed by `grant-postgres-runtime.ts`. Enabling the application binding now fails closed. A later cutover must define and prove a per-request database authorization boundary, install a reviewed grant, complete/backfill the store through a formal migration, benchmark the full-history audit, and verify all seller response surfaces and legacy repair interactions. C04.7 is still open. The owner-only function is for local review, not a production endpoint.

The [native PG18.6 result](./C04-postgres-credited-usage-reader-v344-results.json) passed **11/11 stages and cleanup** on a fresh loopback cluster with exact formal PG73 and v338/v339/v340 proposals. It verified pre-backfill refusal, audited replay, pending exclusion, direct arbitrary-key probes by the runtime LOGIN returning `42501`, owner transfer and a new owner's credit, refusal when a source trigger is disabled, and another arbitrary-key denial after running the real broad runtime grant routine. The three targeted [adapter tests](../../../../packages/admin/lib/shared-key-credited-usage-reader.test.ts) passed, as did `npm run typecheck -w @octafuse/admin` and `git diff --check`.
