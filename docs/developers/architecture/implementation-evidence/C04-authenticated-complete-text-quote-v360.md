# C04 atomic complete flat-text request quote (v360 review proposal)

2026-09-25. The [v360 SQL proposal](../../../../packages/core/migrations-proposals/postgres/authenticated-complete-text-quote-v360.sql) closes the *one-target quote-fragment* gap for a strict OpenAI Chat platform-credential subset. It has not been applied as a formal migration or enabled in a Worker. The [isolated PostgreSQL 18.6 report](./C04-authenticated-complete-text-quote-v360-report.json) records **11/11 passing stages and successful cleanup**.

## Contract and claim

`issue_complete_flat_text_quote_v360(request_id, capability, original_body_sha256, final_body_utf8)` runs only through the new direct `cinatoken_gateway_complete_text_quote_issuer` LOGIN. It checks the one-use v356 capability, current Key/User/personal Workspace, and the exact UTF-8 final body supplied to it. The body must be **at most 1 MiB** and contain an ordered, deduplicated `models` array (maximum eight) beginning with `model`, ordinary string-only messages, and a restricted set of text Chat controls. This tighter size cap intentionally rejects larger requests even though ingress permits up to 50 MiB. The function computes and persists `final_body_sha256`; the v356 digest remains the original pre-transform body hash. PostgreSQL cannot prove that preset and Guardrail processing legitimately transformed one body into the other. The future credential holder must check that the sent body and candidate list match this committed final digest.

For each candidate model, the issuer enumerates **every current active model route** as a conservative superset of surface and ordering selection. Active default OpenAI Chat surfaces whose pool contains a different model's route are rejected: the Worker can select that target by pool ID even though a model-ID enumeration would miss it. Same-model exact/wildcard surfaces and legacy fallback remain covered by the all-route superset. The issuer accepts the whole request only if every such route has a verified, unexpired flat-text Endpoint, a matching independently attested v359 route-source generation, active platform provider and pool, a direct default OpenAI Chat passthrough topology, a platform credential source, and a finite USD price. Any active BYOK Key in the Workspace, shared-channel route, non-null user cost factor, route override, unsupported pricing dimension, missing candidate, stale attestation, or unsupported body rejects the **entire** quote. It does not silently omit a path because a Worker might choose it later.

The issuer takes no caller-supplied target IDs, credential classes, tariff JSON, or amount. It stores one immutable parent and one immutable manifest row per `(candidate index, target, platform provider credential)` in the same transaction, then consumes the v356 capability once. The parent ceiling is checked `3 × max(per-attempt DB-derived ceiling)`; one micro-unit is added to a positive per-attempt raw amount for billing rounding. An explicit output limit above the Endpoint context is included in the ceiling. The manifest binds the final model order, route/Endpoint/provider IDs, ciphertext source hash, v359 source generation and attested digest, price snapshot, and individual ceiling. Broad table-level source locks are acquired **after** capability, Key, User and Workspace validation; they prevent a route or BYOK phantom appearing between enumeration and quote commit in this review implementation. They are not a production throughput design.

The native fixture proves a two-model, three-route plan, including an expensive route that a one-target fragment would miss: per-attempt ceilings 6,001 / 30,001 / 12,001 micros yield a complete 90,003-micro three-attempt ceiling. It also proves a larger explicit output cap raises the ceiling, and a cross-model surface fails closed. A wrong capability, invalid final body, missing model list, active BYOK, shared-channel provider, and one unpriced fallback route fail without an incomplete parent or capability claim; direct runtime and issuer table access are denied.

## Remaining C04 gate

This quote is **not a budget reservation or physical dispatch grant**. The current Worker does not consume this table. A successor admission function must read held amounts only from this committed parent; each pre-send grant must match a manifest row, live Key/source and credential revisions, and a maximum of three committed attempts. The secret holder must verify the committed grant and exact physical `(model,target,credential,final-body digest)` before fetching. New routes after quote commit are absent from the manifest and must be refused at grant. Ambiguous grant acknowledgement must never cause a second ungranted send. Shared Key, BYOK, service-tier, discounted, and other billing classes require separate fully priced manifests or an explicit fail-closed production policy. Production role provisioning, formal migration, D1/MySQL parity, Linux CI, and real Chat integration remain open; C04 acceptance items are not satisfied by this review proposal alone.
