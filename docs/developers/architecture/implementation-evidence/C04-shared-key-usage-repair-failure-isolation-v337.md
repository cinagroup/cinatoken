# C04.7 v337：修复任务失败隔离与死信候选

2026-09-24；**隔离 PostgreSQL 18.6 夹具通过，所有 SQL 仍为 review-only，未安装正式迁移、执行远端 SQL 或部署。** [机器摘要](./C04-shared-key-usage-repair-failure-isolation-v337-results.json)固定本轮报告和主要源码摘要。v336 的 grant、runner 与 Wrangler 源码摘要是当时的历史快照；本轮修改了这些候选，v337 的摘要取代其当前源码声明。v335 的基础修复任务 SQL 摘要 `7b2f288e…716c173d4` 保持不变，避免破坏旧提案与历史回填生成器的固定输入。

[后续提案](../../../../packages/core/migrations-proposals/postgres/shared-key-usage-repair-failure-isolation.sql)只能由直接 migrator LOGIN 在显式事务中用 `cinatoken.shared_key_usage_repair_failure_activation='reviewed-v2'` 激活。它先对 `schema_migrations` 取 SHARE 锁、对 `shared_key_earnings` 取 SHARE ROW EXCLUSIVE 锁，随后核验 0073、基础队列函数、不可变收益 UPDATE/DELETE/TRUNCATE 防护、收益入账触发器及其函数体；锁阻止并发版本行写入或触发器 DDL 在目录检查与安装之间穿过。它在原任务表添加有约束的失败状态，以 `GREATEST(available_at,retry_after)` 的部分索引选择可尝试、非死信任务。v335 的收益入队触发器保持原样：新收益只刷新 `request_log_id`、`requested_at` 和 `available_at`，**不清除**退避或死信状态。因此高频新收益不能让故障 Key 绕过退避；死信 Key 的任务仍保留，等待人工处理。独立函数 DDL 不受收益表锁约束；目录函数体在激活期间稳定仍依赖可信 migrator 的串行变更纪律，当前夹具没有证明任意并发函数替换下的稳定性。

专用 `attempt_one_shared_key_usage_repair()` 先锁 Key 再锁任务，匹配收益入队的锁序。每个 Key 的身份核验、收益汇总、投影更新与任务删除在 PL/pgSQL 异常子事务中执行；**可捕获的 SQL 错误**使该 Key 的投影和删除回滚，外层事务记录 SQLSTATE、次数与下一次时间。第 1–4 次失败分别延后 **1、2、4、8 分钟**；第 5 次标为死信且不再自动候选。函数返回 `repaired`、`deferred`、`dead_lettered` 或 `no_candidate`，在可捕获失败后下一次调用可选择其他到期 Key。`WHEN OTHERS` 不捕获 PostgreSQL 的 query cancellation/assert failure；超时、取消或连接失败会使整次事务失败。**同一个慢 Key 若反复触发超时，仍可挡住后续健康 Key**，本轮没有解决该饥饿路径。

死信只能由直接 migrator LOGIN 人工恢复。操作员先调查并修复原因，从任务的 `last_failed_at` 计算与时区无关的原生精度版本令牌 `md5(to_char(last_failed_at AT TIME ZONE 'UTC','YYYY-MM-DD HH24:MI:SS.US'))`，再于事务中设置 `cinatoken.shared_key_usage_repair_requeue_activation='reviewed-v2'`，调用 `requeue_shared_key_usage_repair_dead_letter(key_id,token)`。令牌不匹配或无死信行会回滚；恢复仅清除失败状态并重排任务，不修改不可变收益或重新入账。专用 consumer 与普通 runtime 都无此函数或任务表权限。

[专用 LOGIN 生成器](../../../../scripts/db/cutover/build-shared-key-usage-repair-direct-login-grant.ts)现要求固定的基础与后续提案 SHA，审查安装后的新旧函数体、上游收益防护和目标库权限，再**只授予新 attempt 函数**。旧 `repair_one_shared_key_usage()` 与人工 requeue 函数对专用 LOGIN 均关闭；[普通 runtime 授权脚本](../../../../scripts/db/cutover/grant-postgres-runtime.ts)兼容未安装后续提案的 v336 状态，在新提案存在时只允许固定专用角色的新入口，并在重跑时收回普通 runtime 对两代入口的权限。[Cron runner](../../../../packages/proxy/src/runtime/shared-key-usage-repair-worker.ts)按事务区分 repaired/deferred/deadLettered 计数；`processed` 表示尝试过的 Key 数，仍受每轮 20 Key／25 秒准入限制。激活值已升为 `SHARED_KEY_USAGE_REPAIR_ENABLED=reviewed-v2`，[Wrangler 生成器](../../../../scripts/deploy/gen-wrangler.mjs)拒绝旧 `reviewed-v1`，默认生成配置仍无修复 binding 或开关。
