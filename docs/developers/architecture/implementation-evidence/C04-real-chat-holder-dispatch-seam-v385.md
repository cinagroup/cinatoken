# C04 real Chat to private holder dispatch seam (v385)

2026-09-26. **Review only, default unwired.** The [v385 Gateway seam](../../../../packages/proxy/src/services/complete-chat-holder-dispatch-v385.ts) accepts the post-preset/post-Guardrail [`FinalChatQuoteInput`](../../../../packages/proxy/src/services/chat-final-quote-input.ts) already captured by the real Chat route, its current body/parser/plan, selected route, authenticated API-key identity, bearer, Guardrail intents, dedicated PostgreSQL connection strings and a private Service Binding. It exposes no provider KEK port. An instance enters once before any asynchronous work.

The default code path awaits the [v360 direct LOGIN quote client](../../../../packages/proxy/src/services/postgres-complete-chat-quote-v360.ts) and the [v361 no-amount admission client](../../../../packages/proxy/src/services/postgres-complete-chat-admission-v361.ts), which each require COMMIT and client-close acknowledgement. It snapshots the authenticated identity, bearer and Guardrail intents before the first await and rejects any caller mutation before admission or delivery. After checking request ID, final-body SHA-256, ordered model IDs, quote ID, ceiling, Guardrail count, expiry and current plan, it creates the existing [six-field v363 envelope](../../../../packages/proxy/src/services/chat-text-holder-request-v363.ts). The only Service Binding payload is `requestId`, `quoteId`, `attemptNonce`, `candidateIndex`, `routeTargetId` and `finalBodyUtf8`. The private holder must independently reload the committed quote and route and obtain its own v362 grant, v365 custody and send-start before fetch. The seam returns only a 200 SSE or JSON body with `Content-Type` and `Cache-Control: no-store`; it drops other upstream/private response headers.

The seam has no legacy Chat budget owner, proxy, usage writer or release callback. Once a quote or admission acknowledgement is uncertain, it does not call the holder. If the Binding rejects after admission or a physical send, the ordinary and Guardrail holds stay unresolved; the seam neither releases nor retries them. The existing v362 SQL rejects a distinct second attempt nonce while an earlier grant is unknown (`pending_unknown`), so the holder must enforce that durable fence. A JavaScript instance latch alone is insufficient across Worker instances.

Source pins and bounded test scope are recorded in the [v385 report](./C04-real-chat-holder-dispatch-seam-v385-report.json).

The v360 and v361 SQL/client paths have separate owned PostgreSQL 18.6 evidence in [v360](./C04-authenticated-complete-text-quote-v360.md) and [v361](./C04-complete-text-quote-budget-admission-v361.md); [v384](./C04-complete-text-observed-holder-v384.md) verifies the private holder and its grant/start/fact chain with PostgreSQL. ## Current activation blocker

The [real Chat handler](../../../../packages/proxy/src/routes/v1/chat.ts) captures `FinalChatQuoteInput` but its `POSTGRES_CHAT_BUDGET_OWNER_ENABLED` branch still opens `openPostgresChatBudgetRequestOwner` and sends via `proxyChatCompletions`. The executable [Chat dispatcher test](../../../../packages/proxy/src/routes/v1/request-dispatch-limit.test.ts) shows this branch can send through that old route after its owner grant. No production binding or activation switch calls v385; the [v364 Service Binding fixture](../../../../packages/proxy/scripts/staging/chat-holder-gateway-v364.ts) is synthetic. The public Gateway's [`SHARED_KEY_ENCRYPTION_SECRET` binding](../../../../packages/proxy/src/app.ts) also remains available to existing routes, so v385's secretless API is not proof of a deployed secret split.

Before the route can switch, an atomic review must replace the old owner/settlement path with v360 quote, v361 admission, v385 delegate and a typed platform result/financial closer; configure separate issuer, admission and holder LOGIN bindings plus a private Worker Service Binding; and verify the full request under real Worker/Hyperdrive cancellation and lost-ACK conditions. The v385 response filter intentionally accepts only 200 SSE or JSON in this review path; it does not preserve the real Chat route's full upstream error, fallback, metadata or streaming settlement behavior. A trusted Provider bill or complete zero-charge authority and four-hold atomic close remain unavailable. Keep C04 acceptance gates open.

For the OpenRouter [generation-cost source candidate](./C04-openrouter-generation-cost-candidate-v372.md), the current generic v385 path deliberately does not add a `user` field. A separate pinned OpenRouter route must create a server-owned per-attempt correlation value **before** v360 freezes the final body, preserve it through v365's upload, observe a generation ID and establish actual cross-key lookup and `external_user` echo behavior. Inserting `user` into every compatible Provider request would change behavior without a documented route pin. No such Provider/source proof or paid call is part of v385.
