# C04 v375 buyer terminal read proposal

2026-09-25. **Review only; default off; not a production cutover.** The [v375 SQL proposal](../../../../packages/core/migrations-proposals/postgres/legacy-buyer-terminal-reader-v375.sql) and [direct PostgreSQL client](../../../../packages/core/src/db/postgres/legacy-buyer-terminal-reader-v375.ts) add a read-only response for the narrow v372 non-grant, current-epoch, held `actual`/`actual` buyer transaction. They do not change the [v372 critical writer](../../../../packages/core/src/db/postgres/critical-writes.impl.ts). No caller currently invokes the reader after a failed or unknown writer COMMIT.

## Terminal decision

The proposal creates a separate `cinatoken_buyer_terminal` schema and grants a dedicated `cinatoken_gateway_buyer_terminal_reader` LOGIN only schema `USAGE` and function `EXECUTE`. It grants no direct Gateway or economic table access. Its `SECURITY DEFINER` function pins `search_path`, verifies `SESSION_USER` and `READ COMMITTED`, and performs only `SELECT` statements. The client requires explicit `review-only` opt-in and a separate PostgreSQL connection carrying that reader LOGIN. It never calls the financial writer.

For one request, `confirmed` requires exact expected user, API key, Workspace, micro amount, token counts, settlement reason, and every economic attempt fact. The stored v2 event must match the append-only buyer log. The event's request ID must join the trusted buyer-log `xid8` marker, and that full transaction ID must join the buyer budget receipt with the expected net spend and hold release. The ordinary hold and Guardrail hold rows must be in the narrow settled state. A missing log, or a present event whose budget receipt has been pruned, returns `unconfirmed`. A committed old log without the marker/event and any mismatched committed facts return `conflict`. **Neither `unconfirmed` nor `conflict` permits a financial replay.** The caller must retain its pre-write expected facts and reconcile elsewhere when the reader cannot confirm.

This is a strict read of existing receipts, not a new immutable intent receipt. The expectation covers economic attempts but is not a digest of the entire request payload: route, protocol and Provider request data are not bound. The Guardrail hold rows have no separate transaction marker, and unreserved window changes, audit and daily stats likewise lack a request-scoped same-transaction marker. Their final values cannot independently prove they were written by the same v371 outer transaction. The buyer amount and usage evidence also remain caller supplied, without an independently authenticated Provider result or bill. These limits keep the path non-activatable.

## Native evidence

The [owned native fixture](../../../../scripts/db/cutover/postgres-legacy-buyer-terminal-reader-v375.native.test.mjs) passed [26/26 stages, cleanup PASS](./C04-legacy-buyer-terminal-reader-v375-report.json) on local PostgreSQL 18.6. It installs all 73 formal PostgreSQL migrations, the exact v368 buyer function body, v371/v372 proposals, real v2 economic producer and budget receipt proposals, buyer LOGIN split and ordinary admission. Its buyer app rights are temporary fixture grants; the separate terminal role has no direct table privileges.

The fixture confirms an exact v372 application write from the dedicated reader connection, then rejects eight changed expectations, including identity, amount, token, reason, attempt ID and evidence hash. It checks no committed log before the write, an application failure after the event that rolls back, and a committed legacy log without economic receipts. It closes a committed writer connection and confirms again from the independent reader. After a privileged local deletion simulating receipt retention, the log and event remain but the result becomes `unconfirmed`. This last case models missing receipt behavior; it does not install or exercise the v346 maintenance job. The fixture does not physically drop a COMMIT ACK on the network, so connection closure after acknowledged COMMIT is not evidence of that transport fault.

Repository-wide Core `tsc --noEmit` remains red on pre-existing unrelated test typings and missing `vitest`; it reports no diagnostic in the new v375 TypeScript helper. `git diff --check` passed for tracked changes. No formal migration, production role credential, remote database, Worker or Provider was changed.
