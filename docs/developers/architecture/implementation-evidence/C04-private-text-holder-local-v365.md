# C04 v365 private text-holder local composition

2026-09-25. This is a default-unwired local composition and loopback proof, not live Chat dispatch or C04 acceptance.

[`private-complete-text-holder-v365.ts`](../../../../packages/proxy/src/services/private-complete-text-holder-v365.ts) accepts exactly the six v363 envelope fields. Its injected private readers load the committed quote, selected route and stored Provider ciphertext independently. The holder checks the exact quoted body hash, candidate and route, decrypts the v2 envelope under its private key input, derives the OpenAI Chat URL and bearer, and freezes its own transformed JSON upload. The raw upload SHA-256, canonical JSON SHA-256, URL hash and bearer fingerprint come from that frozen upload. It calls the v362 grant port with its own claim, then requires a fresh holder-run custody claim and a fresh one-shot send-start receipt with the same grant, lease epoch and raw upload hash. Only after those acknowledgments does it invoke one `POST` with `redirect: 'error'`. It returns the raw `Response` and passes request cancellation to fetch. It waits for upload resource cleanup before returning response headers; that cleanup is not proof of remote receipt or billing.

[`postgres-complete-text-send-start-v365.ts`](../../../../packages/proxy/src/services/postgres-complete-text-send-start-v365.ts) is a dedicated direct-LOGIN client for the proposed custody and send-start functions. Each call uses a one-connection transaction, checks the holder LOGIN and `READ COMMITTED`, waits for transaction COMMIT and one-shot client `end()` acknowledgment, then exposes `commitAcknowledged: true` only for a fresh, identity-matching result. Replay, conflict, stale/expired result, lost COMMIT and lost close ACK return no send authority. The client close promise is not a separate server-side socket-close observation.

Local tests use a synthetic ciphertext and loopback HTTP provider. They cover one successful streaming POST, early response headers while a large request upload continues, wrong body/candidate/source/bearer, unknown grant/custody/send-start ACK, replay, cancellation before fetch and after stream headers, and redirect refusal. The typed client tests cover two independent COMMIT/close ACK sequences, direct role rejection, replay and response identity mismatch.

The holder starts a conservative 14-minute `AbortSignal.timeout` before the grant call and combines it with caller cancellation for physical fetch. This is shorter than v362's 15-minute hold recovery lease even when grant, custody or send-start close ACKs wait; those waits consume the same local allowance. It rejects expired local allowance before custody and send-start, and rejects a send-start receipt whose expiry exceeds custody expiry. A loopback SSE that stays open is aborted at an injected shorter test bound; delayed grant and custody calls cannot reach physical fetch after that bound. The complete quote/holder/private-reader suite passes **50/50** and Proxy typecheck passes. This local timer is a stopgap: a suspended Worker timer or clock skew is not a durable all-hold lease or proof that legacy recovery writers are fenced.

The holder ports are not wired to production DB readers, Worker bindings or the live Chat driver. Existing gateway runtime still decrypts Provider keys and shares the current KEK domain. The proposed v365 SQL remains review-only pending a coordinated cutover. This local holder has no result writer, long-stream lease renewal, provider bill reconciliation or economic terminal; the separate v366 append-only result-fact proposal is also unwired. A successful response here says nothing about completing C04.1–8/G.
