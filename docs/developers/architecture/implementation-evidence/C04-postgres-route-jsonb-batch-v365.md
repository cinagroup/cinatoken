# C04 PostgreSQL route batch JSONB parameter repair (v365)

2026-09-25. The v364 native grant-client check exposed a postgres.js parameter rule that also affected four production repository reads. The PostgreSQL model-endpoint repository sent `JSON.stringify(ids)` to `jsonb_array_elements_text($1::jsonb)` in `listRouteLinks`, `listDiscoveryRouteBindings`, and `listRuntimeBindingsByRouteTargetIds`. The route-data-policy repository used the same pattern in `getByRouteTargetIds`. postgres.js encoded the string as a JSONB **string**. Array expansion then failed with `cannot extract elements from a scalar`, preventing these route/policy reads from returning a candidate list.

All four calls now pass `pg.json(ids)`. The [isolated PostgreSQL native test](../../../../packages/core/src/storage/postgres-jsonb-batch-native.test.mjs) first proves the old parameter shape fails, then calls the actual four repository methods against minimal route, endpoint, and policy tables. It verifies matching and missing IDs; **1/1 passed** on PostgreSQL 18.6 with cluster cleanup. The Core model-endpoint suite passed **40/40**, and Proxy typecheck passed. The native fixture is registered in the local CI workflow for Linux execution; that CI run has not occurred here.

This repair supports existing route discovery and the planned secretless ingress projection. It does not remove the gateway's Provider credential reads, create a private holder, prove independent policy attestation, or complete C04. The test uses an isolated database with minimal tables, so it is not an old-database migration or production-load check.
