# C04 complete Chat request quote: executable gap audit (v358)

2026-09-25. **Source audit and local tests, not a quote issuer.** This note checks whether the [v356 authenticated request capability](./C04-authenticated-quote-db-boundary-v356.md) and [v357 DB-derived one-target text ceiling](./C04-authenticated-text-route-ceiling-v357.md) can currently be composed into an independently verifiable, complete Chat request quote. They cannot. Do not pass `three_attempt_ceiling_micros` from the v357 fragment to v350/v351 as the entire request hold, and do not treat a consumed v356 capability as dispatch permission. No SQL, role, production route, or database state is changed by this audit.

## Source-backed coverage test

| Required fact for a complete quote | Current source and observed boundary | Missing DB-verifiable condition |
| --- | --- | --- |
| Exact candidate models and request shape | `chat.ts` resolves a preset, runs input Guardrails, then reparses `model`/`models` and calls `buildModelFallbackPlan`. [`model-fallbacks.ts`](../../../../packages/proxy/src/services/model-fallbacks.ts) permits up to eight distinct OpenAI models. [v356](../../../../packages/core/migrations-proposals/postgres/authenticated-request-capability-login-v356.sql) stores a caller-asserted body SHA-256, not the post-preset/post-Guardrail body or its model list. | Issuer must derive candidate IDs from the actual final normalized body, bind its digest to the quote, and ensure the credential holder sends only that bound body/model. An asserted list of one model or one route cannot prove the rest of the fallback plan is absent. |
| Every eligible route target | [`model-fallback-plan.ts`](../../../../packages/proxy/src/services/model-fallback-plan.ts) resolves each model and surface, then applies output capacity, ZDR/data policy, provider preferences, max price, performance, default load balancing, service tier, and model/global partitioning. [`model-router.ts`](../../../../packages/proxy/src/services/model-router.ts) can fall back from a surface lookup to legacy active routes and validates Endpoint binding/fingerprint before returning a target. [v357](../../../../packages/core/migrations-proposals/postgres/authenticated-text-route-ceiling-issuer-v357.sql) accepts exactly one caller-selected target. | A DB issuer must calculate and persist a complete permitted `(candidate index, model, target)` set, or a documented DB-derived superset, from the same authoritative rows. A grant must reject any target outside it. For an exact set, routing rules and their source revisions must match the Worker; a superset can reserve more but may fail closed on irrelevant unsupported routes. |
| One-shot quote transaction | v357 inserts one fragment keyed by `request_id`, then changes the v356 capability from `issued` to `claimed`. A second v357 call for another target returns stale; there is no aggregation or parent quote relation. | A full-plan issuer must write all manifest rows and their aggregate in one transaction before consuming the one-use capability. Repeating the one-target issuer is not a valid composition. |
| Credential identity and financial basis for each target | [`failover-dispatch.ts`](../../../../packages/proxy/src/services/failover-dispatch.ts) expands ordered targets with shared Keys and then private BYOK immediately before dispatch. [`shared-key-pool.ts`](../../../../packages/proxy/src/services/shared-key-pool.ts) clones a target for each eligible seller Key and a platform fallback. [`byok-key-pool.ts`](../../../../packages/proxy/src/services/byok-key-pool.ts) keeps the same target while inserting primary/fallback private credentials and can suppress shared/platform capacity. Its test shows one target with `byok:primary-1`, `sharedkey:shared-1`, platform `provider-1`, and `byok:fallback-1`. [v357](../../../../packages/core/migrations-proposals/postgres/authenticated-text-route-ceiling-issuer-v357.sql) records no selected credential. | Quote or pre-send grant must bind `(target, credential class, credential ID, owner, billing mode)`. Shared-Key grants also need the current immutable seller quote/version and commission. BYOK, shared, and platform attempts cannot reuse one untyped financial intent merely because their route target is equal. The actual secret holder must refuse a missing or mismatched committed grant. |
| Complete amount from immutable DB facts | [`guardrail-budget-estimate.ts`](../../../../packages/proxy/src/services/guardrail-budget-estimate.ts) currently computes an in-process max across candidate routes using Endpoint prices, route price schedules, user charged factors, request/default output caps, and distinct BYOK standard-price basis. [`endpoint-billing-pricing.ts`](../../../../packages/proxy/src/services/endpoint-billing-pricing.ts) handles Endpoint discount, cache rates, and unsupported usage dimensions. [`service-tier-billing.ts`](../../../../packages/proxy/src/services/service-tier-billing.ts) may select a different eligible tier's pricing route after provider usage arrives. v357 handles only USD flat text on one default OpenAI Chat passthrough target with no user factor or route override. | For every permitted credential-expanded attempt, the DB must either derive a finite conservative amount under the actual buyer/Guardrail/BYOK rules and bind all source versions, or reject the request before a send. A missing currency, unbounded usage dimension, unknown rate, unsupported factor/tier, or stale source cannot be interpreted as zero. |
| All possibly billable sends | [`request-dispatch-budget.ts`](../../../../packages/proxy/src/services/request-dispatch-budget.ts) limits a request to three nonrefundable pre-fetch permits. The per-model loop and global `partition=none` dispatcher share that budget; an earlier failed attempt may still be billable. | Once every selectable attempt has a DB-derived ceiling, a safe request hold is at least `3 × max(per-attempt ceiling)` with checked arithmetic, including failed/unknown attempts. The amount alone is insufficient: the quote must enumerate what may consume a permit, and pre-send grants must cap the committed permit count at three. |
| Mutation and physical egress boundary | v356 invalidates on security-sensitive Key/user/Workspace changes. v357 copies route/Endpoint data but its persisted subject fingerprint can be stale; edits can also restore an earlier value (ABA). The ordinary runtime still holds provider credentials, and current quote/attempt records are written by the same Worker that can send. | Quote/grant must check a monotonic route/provider/Endpoint and credential revision after lock waits, plus current Key/Workspace status. A separately controlled credential holder must verify committed `(quote, attempt, target, credential, revision)` before fetch. SQL rows alone cannot prove which secret or URL was physically used. |

The single-target counterexample is executable in the current local suite: `byok-key-pool.test.ts` expects four credential identities at one target, and `shared-key-pool.test.ts` expands two targets to five attempts. The source also supports a second, differently priced fallback target or model. Therefore even a fresh one-target `3 × per_attempt` fragment can omit a more expensive eligible target, while one target ID alone cannot decide whether the hold is ordinary buyer, shared seller, or private BYOK Key-limit money.

## Next implementation slice and acceptance gate

1. **Define the issuer/egress input contract before another SQL issuer.** Expose the final post-preset/post-Guardrail normalized Chat body and model candidate order with an immutable digest. Issue v356 against that final digest, or extend the capability with an explicitly linked final-body digest; the pre-transform digest cannot silently stand for a rewritten request. Retain the v356 bearer verification as identity proof. The trusted egress holder must compare the body/model and physical `(target, credential)` against a committed quote/grant; otherwise the DB cannot independently tell whether a caller omitted a fallback or changed the send after quotation. The quote may use a DB-derived conservative superset of routes, but its grant must reject every unlisted send.
2. **Produce an insert-only full-plan manifest under a distinct direct LOGIN.** The issuer should take `request_id`, v356 capability and final body; it must not take a numeric amount, caller price JSON, credential class assertion, or caller-selected route list. It must parse up to eight candidate models, resolve the current authoritative surface/legacy route sources and all credential classes that could be selected, and persist one row per permitted `(candidate index, target, credential identity/billing basis)`. A dedicated metadata-only DB reader must expose active BYOK/shared/provider credential IDs and revisions without giving the quote issuer decrypted secrets. Persist source generations, Endpoint/tier tariff, route factor schedule, user factor, currency/unit, seller quote version/commission where applicable, per-attempt ceiling, and checked `3 × max` ordinary/Guardrail/BYOK holds. Unsupported or unbounded facts reject the whole quote. Write all rows and the aggregate before consuming v356 once. Ordering may be omitted from the financial maximum but candidate membership may not.
3. **Make reservation and grant consume the manifest.** A successor to v350/v351 must read held amounts and intents solely from that manifest under the same request lock and reject a one-micro substitution. Each pre-fetch grant checks a permitted manifest row, live Key/source revisions, the correct basis for platform/shared/BYOK, committed holds, and a maximum of three distinct attempt IDs. A selected shared-Key claim must have the same request/target/Key/seller quote as the grant. The egress holder checks grant COMMIT acknowledgement and exact physical secret/endpoint; an unknown acknowledgement means zero new sends until resolved by exact lookup.
4. **Build a native and real-Chat counterexample fixture before enabling.** One authenticated request should include two fallback models, at least two differently priced targets, a target with primary BYOK/shared/platform/fallback BYOK expansion, and a service-tier alternative. The fixture must prove the DB's quoted set covers every actual selectable `(candidate,target,credential)` and that the hold equals or exceeds three times the largest DB-derived billable attempt. Negative cases must include an omitted target, changed/ABA tariff or credential, wrong billing basis, unexpected fourth permit, a one-micro admission call, absent seller quote, and failure/unknown of the grant COMMIT acknowledgement; each must yield zero upstream fetches. Compare persisted quote and buyer/outbox attempt references after successful and failed sends. Test the source-revision gate independently before claiming coverage.

The local audit command `npm exec -- tsx --test packages/proxy/src/services/shared-key-pool.test.ts packages/proxy/src/services/byok-key-pool.test.ts packages/proxy/src/services/model-fallback-plan.test.ts packages/proxy/src/services/guardrail-budget-estimate.test.ts` passed **63/63** on 2026-09-25. These tests establish current expansion and planning behavior, not a DB-issued complete quote or egress grant. Formal migration, production role isolation, Worker/Hyperdrive credentials, and D1/MySQL parity remain separate gates; C04.1–8/G cannot be checked from this audit.
