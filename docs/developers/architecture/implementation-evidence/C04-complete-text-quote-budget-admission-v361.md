# C04 complete Chat quote budget admission (v361 review)

2026-09-25. [`complete-text-quote-budget-admission-v361.sql`](../../../../packages/core/migrations-proposals/postgres/complete-text-quote-budget-admission-v361.sql) is a review-only PostgreSQL proposal. It accepts `(request_id, quote_id, Guardrail intents)` and derives the held amount from the committed v360 parent and route manifest. It rechecks the authenticated Key/User/Workspace, active source and credential basis, complete route set, current Guardrail sources, and server-clock expiry under locks. One transaction reserves the same `3 × max` ceiling for ordinary and all applicable Guardrail budgets, then inserts an immutable admission receipt. The activation transaction revokes the old caller-amount v350/v351 reserve functions from the admission LOGIN and grants only the no-amount wrapper.

The [native PostgreSQL 18.6 fixture](../../../../scripts/db/cutover/postgres-complete-text-quote-budget-admission-v361.native.test.mjs) passed **1/1 test, 10/10 stages, cleanup PASS**. The [report](./C04-complete-text-quote-budget-admission-v361-report.json) records source hashes and the 90,003 micro-unit hold for one ordinary and three Guardrail sources. It also verifies old direct reserve calls are denied; zero or omitted Guardrail intents cannot bypass configured budgets; exact replay creates no second hold and preserves ordinary hold status; changed route/credential/BYOK basis, wrong quote identity and expired Key reject. The [`v361 direct-LOGIN client`](../../../../packages/proxy/src/services/postgres-complete-chat-admission-v361.ts) supplies no amount, checks the returned amount/digest/count/expiry, and treats uncertain close acknowledgement as unsafe. Its focused tests passed **5/5**; the combined quote/admission/grant-contract suite passed **20/20**, and Proxy typecheck passed. The fixture is registered in local CI; Linux CI has not run.

The [`text grant egress contract`](./C04-text-grant-egress-contract-v361.md) passed structural tests but is unused. It includes a counterexample in which a same-Worker echo accepts an unrelated plaintext bearer, showing why an independent secret holder and broker are still necessary. The [requirement map](./C04-current-requirement-evidence-map-v361.md) records each C04.1–8/G gap.

The v361 proposal is not a formal migration and has not been wired into the Chat handler. Activating it independently would revoke the amount-taking functions used by the existing opt-in v350/v351 adapters, so the runtime switch must be coordinated. The proposed broad table locks have not been assessed at production load. Admission does not grant a physical send, verify the public-body-to-wire transformation, recover a Worker death after fetch, or settle actual/unknown provider cost. No remote SQL, deployment, cloud call, or production credential change was made; formal migration counts remain PG 73, D1 68 and MySQL 64. C04.1–8/G remain unchecked.
