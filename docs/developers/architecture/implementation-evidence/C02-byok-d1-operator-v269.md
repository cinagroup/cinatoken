## 本轮交付

新增 `scripts/deploy/byok-d1-operator.mjs`，不再要求调用方手工散拼各个变更方法。唯一执行入口 `run()` 在首次外部读取前获取原有不可释放的工作区占位；同对象再次调用返回同一结果，新对象不能接管已存在占位。构造/导入不创建文件、不发送网络请求；不自动发现凭证，没有可直接部署的 CLI。

执行顺序固定为：预检 → 双轮关闭观察 → 接收端/controller/gateway 部署并回读 → 创建临时 Access 令牌 → 开放受保护 gateway → 原生安装围栏 → 捕获基线/认领控制/开围栏 → 十个用例及各自独立 D1 回读 → STOP/封闭围栏 → 关闭 gateway 和 Access → 新鲜关闭观察 → 发放维护许可 → 开放维护 controller → 一次清理 → 关闭 controller/Access/撤销令牌 → 再次双轮关闭观察 → 独立数据库最终核对。

成功完整路径使用 **93/128** 条日志记录，无需增加现有容量或删除历史记录。清理的成功 HTTP 回执不是最终验收；最终核对另行通过固定 staging D1 管理入口读取数据。默认退出状态是保留关闭围栏和 finished 维护许可，不拆除十五个触发器、不重置许可、不恢复旧实验部署或入口。

准入数据绑定部署候选指纹、历史证据摘要和完整初始隔离基线摘要，覆盖另外的 staging Worker、生产 settings、Access 与旧令牌。预检必须提供源码冻结、完整旧代码、独占所有权、调用路径清点、实际付费套餐、首轮累计预算和维护时序资格等全部证明；异步 Promise 不能冒充同步开启守卫。证明提供器仍由可信上层收集器提供，本模块不会从布尔字段或日志 ACK 生成这些证明；测试中的合成证明不代表实际云证据。

每次部署、Access 激活及 D1 控制写入连接现有准入守卫。十个用例也逐次重验。维护激活与 cleanup 前增加主机墙上时间及单调时间的 **10 秒** 限制，给既有接收端 **15 秒** 新鲜度规则预留空间；原生许可/时间 SQL 没有改动。这是失败关闭限制，不是“线上时序已能满足”的证明。关闭观察仍为双轮共 55 次顺序逻辑读取，真实网络下的窗口问题继续待解决。

## 失败语义

预检或初始关闭观察失败时不进入云变更。已经进入变更阶段后，仅尝试尚未消费的 STOP、封闭围栏、独立关闭各入口/Access 和撤销令牌；收尾不复用已取消的用户信号。每项仍受组件自己的有限超时约束。

原子写入成功但 ACK 丢失、清理成功但响应丢失、取消、账务/部署资格撤销或最终核对失败均保留 ATTENTION_REQUIRED。即使随后发现 finished 许可、关闭操作成功或已经没有临时令牌，也不把该轮改判成功，不重放未知命令、不自动删除未知样本。不声称超时已经取消远端工作；晚到的开启写入仍需独立复核。

## 独立最终数据库核对

扩展 `scripts/deploy/byok-d1-management.mjs` 的 `verifyFinal()`。只读，无通用 SQL 入口：

- 核对固定 staging 数据库身份、整份 schema 及全部 56 表计数；fixture 控制行必须已消失，五张受保护表必须为空。
- 维护许可必须是本实例刚发放的同一份许可，只有状态/回执发生预期变化；要求 finished、664 行和 143 条语句。
- 读取四类保留表的全部列与有界行，核对原始基线 SHA-256；只排除已完整核对的固定维护许可行，不能任意传入排除列表。
- 在行读取前后重复 schema、计数、关闭围栏及完整许可读取。仍是观察，不宣称 REST 读取构成原子快照或数据库已静默。
- 复用已有有界响应和整体超时；不执行 DELETE、DDL、触发器拆除或许可 reset。
