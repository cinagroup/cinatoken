两次清点失败均保留原始机器结果、日志链、当时源码与本地测试，未覆盖或伪装成功：

1. 初版拒绝了 cinagroup 一条结束早于开始的部署记录。单记录 GET 确认原始时间确实矛盾；改为保留原值并标记 `INCONSISTENT_STAGE_TIMESTAMPS`，不授予可信终态分类。完整清点最终发现两条这样的记录，均 Functions=false。没有推断其上游原因。
2. 下一版在 cinagroup 的 skipped 记录失败。对四条已知跳过记录逐个 GET，均实际返回 `queued / skipped`，而已安装 SDK 的枚举未包括此值。补入实测状态；只有明确 skipped 标志、latest / stages 一致、有结束时间且后续四阶段全部 idle / 无时间，才描述为跳过且未记录部署。状态不一致或信息不足仍保留未解决。
