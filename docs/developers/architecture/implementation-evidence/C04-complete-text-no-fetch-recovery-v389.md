## Durable work and isolated authority

A new v362 grant inserts one job in the same transaction. Grant rollback therefore leaves no orphan job. A bounded scan of at most 50 grants finds missing jobs through an anti-join and unique grant key, without a commit-time watermark. Existing committed resolution/terminal nonces are adopted during backfill. If a legitimate earlier caller commits a different nonce after the job exists, the job keeps its own immutable nonces and the observer returns the actual resolution/terminal ID. The runner advances from that observed result instead of trying to rewrite it.

The direct `NOINHERIT` recovery worker LOGIN may scan, claim and report failures only. Jobs have server-time leases of 5–300 seconds, a monotonically increasing lease generation, at most seven claims per recovery round and bounded exponential backoff. Expired claims count toward the limit. A stale worker cannot observe, fail or finish a successor's lease. Seven unsuccessful claims quarantine the job. A separate operator LOGIN can requeue a quarantined job at most three times, with a durable reason and audit row. Requeue preserves both nonces and does not change any grant, hold, observation or terminal.

The direct observer LOGIN can inspect and finish a current job, but cannot acquire work or invoke the resolver/closer. It locks the job and the same stored request advisory key used by v370/v388 before reading grant, resolution and terminal rows. This prevents several READ COMMITTED statements from combining a pre-resolution row view with a newly committed terminal. It rechecks lease expiry after blocking work. Every public wrapper has fixed search path and server timeout settings; the client also sets timeouts before the actual function query.

Installation verifies the exact table, function, event type, enabled state, absence of trigger predicates/column filters and deferred shape for 13 v388 terminal, log, hold and egress guards. Six critical function bodies are pinned with owner and `SECURITY DEFINER` checks. Explicit default privileges that would leak newly created objects to another role are rejected. The native negative cases replace a constraint trigger with `WHEN (false)`, replace the verifier body with `RETURN NULL`, and add an inherited runtime SELECT grant; every altered installation rolls back.

The inspector returns `ready_to_resolve`, `ready_to_close`, `confirmed`, `possible_send`, `conflict` or `lease_lost`. A possible send remains unknown and is quarantined with all holds intact. Confirmation recomputes the terminal decision digest and joins the exact immutable grant, quote and resolution; it verifies the zero log, same-transaction typed outbox row, ordinary hold and complete Guardrail set. It deliberately does not compare live shared-account/window counters with old terminal snapshots: unrelated legitimate activity can change those counters after closure. Missing or conflicting companion evidence cannot become `confirmed`.

`finish` accepts only a job ID and lease token, reads the facts again and completes a job only for a verified terminal. The caller cannot provide an amount or a claimed completion status. A repeated finish with the committed completion token returns the existing result without rewriting it. `completed` here means the no-fetch financial terminal was independently observed; it does not mean the platform economic event was delivered to a downstream consumer.

## Runner and crash boundaries

The bounded runner scans once, claims a job, observes it, invokes the existing resolver if necessary, observes again, invokes the existing closer if necessary and finishes through the independent observer. Every operation uses the appropriate direct LOGIN on a separate connection. It requires COMMIT and connection-close acknowledgements before proceeding. Any transport or acknowledgement uncertainty stops the run and leaves the durable lease for later recovery. Confirmed semantic rejections can be retried or quarantined; a resolver/closer nonce conflict first causes another fresh observation so an already committed result can be adopted.

The native fixture uses the actual runner for ordinary recovery and for dropped resolver/closer COMMIT responses. It also drops real claim and finish COMMIT responses, discards process-local claim/nonce values and proves a fresh run resumes from the persisted job. The protocol proxy drops PostgreSQL `CommandComplete(COMMIT)` after the real backend commits; it does not alter TCP acknowledgements, emulate Hyperdrive or simulate a deployed worker crash. Deadline/lease acceleration and deliberate deletion of a job or event are owned-cluster fault injections unavailable to runtime roles.

Other cases cover grant/job rollback, bounded backfill of pre-install grants, existing results with different nonces, two concurrent workers, stale leases, observer request-lock timeout, possible-send quarantine, seven-attempt exhaustion, three reasoned operator recoveries, missing-event rejection, historical confirmation after another request reserves capacity and anti-join reconstruction of a missing job.
