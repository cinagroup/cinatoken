# C04 dedicated complete-text grant client (v364 review)

2026-09-25. [`postgres-complete-text-attempt-grant-v362.ts`](../../../../packages/proxy/src/services/postgres-complete-text-attempt-grant-v362.ts) is a default-unwired client for the v362 PostgreSQL proposal. It does not activate the migration, bind a Worker, fetch from a provider, or change Chat dispatch.

The client takes a holder-computed 18-field physical claim and an attempt nonce, copies the primitive fields into an immutable snapshot, checks their exact shape, and sends only that snapshot to `grant_complete_flat_text_attempt_v362` as a parameter. It requires the dedicated direct `cinatoken_gateway_complete_text_attempt_granter` LOGIN. The only accepted database result is `grant_recorded` with every echoed claim field unchanged, consistent source generations and hashes, a valid grant ID and attempt number, and send/hold deadlines. `already_recorded_unknown`, `pending_unknown`, malformed responses, and identity drift cannot create a returned receipt.

The returned `status='committed', commitAcknowledged=true` receipt is created only after the transaction promise resolves and the one-shot postgres.js `end()` promise resolves. A rejected or missing COMMIT/close acknowledgement fails closed; the caller must treat that nonce as unknown and never replay it as another physical send. After both acknowledgements, the client checks the send-start deadline again. The returned receipt is still **not** evidence of actual provider delivery, an accepted response, a bill, or settled buyer/seller money. `end()` is the client library's shutdown acknowledgement, not an independent observation that the raw socket closed on the server.

The local [unit fixture](../../../../packages/proxy/src/services/postgres-complete-text-attempt-grant-v362.test.ts) covers delayed COMMIT and close acknowledgements, each lost acknowledgement, replay status, tampered wire echo, wrong LOGIN, expiry after the acknowledgements, invalid claim before connection, and inherited `toJSON` substitution. The complete quote suite passed **32/32** and Proxy typecheck passed. The [v362 native fixture](../../../../scripts/db/cutover/postgres-complete-text-attempt-grant-v362.native.test.mjs) now calls this same client with a direct LOGIN against isolated PostgreSQL 18.6, then verifies the persisted `unknown` row; **21/21 stages, cleanup PASS**. The first native attempt revealed that sending a JSON string through postgres.js to `$2::jsonb` produced a JSONB *string* and was rejected by the SQL function. The client now uses the driver's `json()` parameter wrapper and preflights the JSONB object type. The native fixture still does not exercise a separate private holder, a real provider, or deployed Hyperdrive.

The next physical boundary is a private holder with its own credential key domain and database role. It must construct the actual URL, bearer and frozen upload, call this client, recheck the committed grant and source at send start, then own one physical POST. The v362 unknown row still has no grant-linked result writer, lease renewal, provider bill reconciliation, or retry unlock protocol.
