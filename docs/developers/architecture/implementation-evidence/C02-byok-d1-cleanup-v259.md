2026-09-16，Checklist v1.158。**本地保护模块通过；真实 Workers/D1 验收和完整云端操作器仍未完成。** 本轮没有部署、云端清理或真实凭证操作；产品 BYOK SQL、Images 结算规则、迁移和云配置未改。

## 实现范围

新增 `byok-d1-cleanup.ts`、独立预期行校验 `byok-d1-cleanup-ownership.ts` 及本地夹具/测试。它们接受原生 `D1Database`，没有 HTTP 入口、自动调用或生产回退。既有一次性处理器仅导出并重命名严格控制记录解析函数，三个文字替换由验证器逐字核对，授权与执行行为不变。

清理前必须提供可信的 **启用样本前基线**：固定 56 表、schema 摘要、68 条迁移记录、12 条静态配置、已撤销的旧 admin 和数据库身份记录。返回值只有计数和摘要，不输出配置/凭证内容。读取 schema、行和控制记录均有界；schema 不符、意外表、超长行、无主键或非预期字段直接拒绝。

只允许清理已明确停止、无 PENDING、所有已完成回执均为 PASS 的用例前缀。独立校验器重建用户/工作区/管理密钥/BYOK/审计的预期关系、固定字段和财务零值。随机管理密钥哈希、审计 UUID 以及部分创建时间只验证格式，**不是原始种子回执的历史摘要比对**；之后事务内仍逐字段核对本次观察到的完整行。远端操作器必须保证随机凭证来源和基线可信，不能把看起来像测试数据的前缀当作删除授权。

`ready`、`pending`、失败回执、STOPPED 中仍有 pending，以及其他不确定状态均留存隔离，不自动清理；HTTP 完成、本地 active=0 或 STOPPED 本身不证明所有原生写入已停止。

## 原子删除边界

清理计划在一个原生 `db.batch()` 中执行：

1. schema、56 表计数和九张相关表的完整行集合守卫。
2. 六条按明确 ID 列表的删除，每条紧随 `changes()` 数量守卫；不使用前缀匹配或全表删除。
3. 再核对 56 表基线计数、四张保留表的完整行集合及 schema。

任一守卫不符会制造 SQL 错误，要求整批回滚；对应 [D1 官方 batch 事务约定](https://developers.cloudflare.com/d1/worker-api/d1-database/#batch)。完整十用例的本地删除计划为 **139 条语句、756,196 字节**，清除内存数据库中 **664 条合成记录**，保留基线。139 不包含前后快照、基线和外部关闭证明的读取，不能作为完整请求或费用总量。

SQL 参数使用每表一份有界 JSON，避免逐行拼接数百条语句；全字段条件采用平衡表达式。计划最多 256 条 / 1 MiB，每条最多 100 个绑定 / 100,000 字节 SQL；快照最多 1 MiB。上限是本模块保护，不是精确账单限额或原生执行时限。按照 [D1 当前限制](https://developers.cloudflare.com/d1/platform/limits/)，该计划不能直接运行于 Free 每次 50 条查询限制；上线前仍须核验现有套餐，不自动升级。

调用者需在首次读取前、删除前和删除后独立证明生产者关闭；第二次证明后持久化脱敏 PENDING，超过 15 秒则不发出删除。只有删除 ACK、基线复读和关闭复核均通过才报告清理完成。若删除已提交但 ACK 丢失，返回需处理状态，不补发删除；ACK 日志失败也不报告完整成功。同一模块实例缓存唯一执行 Promise，**并不提供跨进程独占性**。
