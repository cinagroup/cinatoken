# C04 text holder request envelope (v363 local review)

2026-09-25. The [v363 builder](../../../../packages/proxy/src/services/chat-text-holder-request-v363.ts) is unused. It defines the exact six fields a future independent text holder may receive: `requestId`, `quoteId`, `attemptNonce`, `candidateIndex`, `routeTargetId`, and `finalBodyUtf8`. It passes no Provider route DTO, URL, ciphertext, plaintext key, or caller-supplied wire digest.

The builder checks UUIDs, a live platform quote, matching request and ordered candidate IDs, selected candidate/model, and a nonempty target ID. It encodes the exact final body as UTF-8, enforces the **1 MiB** limit, recomputes SHA-256 against the quote, and checks the body's `model`/`models` order. The [tests](../../../../packages/proxy/src/services/chat-text-holder-request-v363.test.ts) show that serializing the envelope omits a plaintext key, secret host and label present on the supplied route; stale, malformed, mutated and oversized inputs reject. The combined quote/admission/grant/wire/envelope suite passed **27/27**, and Proxy typecheck passed.

This is a same-Worker builder, not an authenticated holder request or send authorization. The holder service and binding do not exist; neither a committed v362 grant acknowledgement nor an independently loaded quote/manifest, route source, credential and frozen upload is established. The builder accepts a Worker-selected target ID and nonce without proving their database authority or uniqueness. The [live Worker repository decorator](../../../../packages/proxy/src/runtime/workers.ts) decrypts `enc:v2:` Provider keys before routing, while the local [v361 grant gate](../../../../packages/proxy/src/services/chat-text-grant-egress-contract-v361.ts) still expects the stored ciphertext hash, so the real route remains fail-closed. A future holder must obtain both stored source and plaintext secret under its own authority, verify the committed grant and exact upload, then own the one-shot physical `fetch`. No remote SQL, deployment or provider call was made; C04.1–8/G remain unchecked.
