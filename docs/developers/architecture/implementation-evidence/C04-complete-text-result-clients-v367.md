# C04 v367 local result-fact clients

2026-09-25. The [v367 client](../../../../packages/proxy/src/services/postgres-complete-text-result-facts-v367.ts) provides two default-unwired, direct PostgreSQL calls for the [review-only v366 fact proposal](../../../../packages/core/migrations-proposals/postgres/complete-text-result-facts-v366.sql). The holder call appends one holder observation under `cinatoken_gateway_complete_text_send_holder`; the bill call appends one bill fact under a separately authenticated `cinatoken_gateway_complete_text_provider_bill` LOGIN. Each checks both `session_user` and `current_user`, READ COMMITTED isolation, and a single-connection transaction. A receipt is exposed only after the function result, COMMIT, and connection-close ACK. Neither call has an automatic retry or generates an evidence nonce. A lost ACK may mean the fact persisted; the caller must retain the same nonce and evidence and must never infer that no send or no bill occurred.

The client requires exact v366 evidence fields and typed values, including bounded ASCII provider references, lower-case SHA-256 digests, and nonnegative token counts. Bill amounts are **decimal text** at the API boundary, then emitted as a JSON numeric literal for PostgreSQL; this preserves 18-digit amounts beyond JavaScript's safe integer range. The client independently hashes the canonical PostgreSQL `jsonb::text` bytes for this narrow flat-ASCII evidence grammar. It binds that text through `$n::text::jsonb`, avoiding Postgres.js JSONB string inference and retaining the numeric literal. PostgreSQL recomputes and checks the digest in v366. A returned digest or fact ID that differs from the bound values is rejected after connection close. The SQL itself copies request, quote, grant, run, send-start and route commitments from server rows; client callers cannot set them. `already_recorded` is an acknowledged replay of the exact same nonce, source, kind, evidence digest, holder run and lease epoch; it does not create send authority.

The [unit test](../../../../packages/proxy/src/services/postgres-complete-text-result-facts-v367.test.ts) passed **7/7**, covering COMMIT and close ACK loss, role separation, bound argument immutability, nonce/event conflicts, invalid evidence, a forged response digest and full 18-digit bill amount. The [owned PostgreSQL 18.6 digest fixture](../../../../scripts/db/cutover/postgres-complete-text-result-client-digest-v367.native.test.mjs) passed **7/7 shapes**, cleanup `PASS`; its [machine report](./C04-complete-text-result-client-digest-v367-report.json) records source hashes and limitations. It uses real Postgres.js parameter encoding and native `jsonb::text`, `jsonb_typeof`, and SHA-256 for every permitted holder kind plus zero and maximum bill amounts. Non-ASCII text, quotes and backslashes in provider references are excluded by both v366 and the client; they are negative unit cases, not supported evidence values.

The digest fixture does **not** install v366 or call a real provider. The [v366 native fixture](./C04-complete-text-result-facts-v366.md) now drives both v367 functions through the installed v366 writer under separate real LOGINs and verifies stored grant/run/send-start binding, exact full-size amount, normal COMMIT/close ACK and one nonce replay. Neither fixture can authenticate an external bill document, provider event, reference or claimed amount. An independent provider-bill intake must establish that provenance and correlate the event to the grant before calling the writer. A holder zero-charge observation remains unverified. No resolver, all-hold lease renewal, buyer settlement, economic terminal or live Worker integration is supplied by v367.
