# C02 v258：BYOK D1 一次性处理器与调用守卫

2026-09-16，Checklist v1.157。**本地保护层通过；真实 BYOK D1 验收仍未执行。** 新处理器没有挂接到 Worker 默认入口，没有部署或创建控制记录。产品 BYOK SQL、Images 结算规则、迁移、依赖和现有云配置未改。

## 已实现

`packages/proxy/scripts/staging/byok-d1-one-shot.ts` 仅接受固定 staging origin 下的 10 个用例及 `stop`，要求空正文 POST、64 个十六进制字符的 Bearer 凭证，不接收自选 run ID、SQL、清理或推理请求。凭证由后续操作器用安全随机数生成；数据库只存 SHA-256 摘要，处理器使用 `timingSafeEqual` 比较。测试中的固定凭证仅用于内存 SQLite，不是线上授权。

控制记录使用现有 `system_config` 的专用 key，无需迁移。数据库读取前按 UTF-8 字节数限制值为 32 KiB，随后严格校验字段、状态、顺序与回执。授权窗口最长 15 分钟，准入 SQL 内使用数据库时钟检查起止时间。操作器未来必须先在关闭、隔离且身份已核验的 staging 中做一次普通 INSERT，不能覆盖或重置旧实例；本模块本身没有创建/重置接口。

执行顺序：

1. 在任何数据库 I/O 前登记 `waitUntil`；登记失败不启动任务。
2. 读取并验证授权，按完整旧值 CAS 写入 PENDING；未收到明确提交确认，不执行用例。
3. 固定顺序调用原有验收程序，转发原 SQL/参数/事务边界，不插入语句、不拆 batch。
4. 等待用例操作收尾后，以原 PENDING 值 CAS 持久化回执，再返回成功。失败为终态；提交确认丢失返回不确定结果，不自动重放。

已消费用例不能再执行；两个请求竞争同一用例只允许一个认领。客户端在认领后断开不触发撤销或清理。`stop` 可在授权过期后封住后续准入，并保留原 pending 信息；进行中的用例不能覆盖 STOPPED。**STOPPED、FAIL、HTTP 结束或本地 active=0 均不自动构成数据库停写证明。** 外层必须核对可能迟到的原生操作，不得因超时删除样本。

## 界限与已知限制

`byok-d1-guard.ts` 为每用例限制最多 200 条 SQL、两次同时未结束的调用、20 秒内启动后续数据库调用、每语句最多 100 个绑定及 100,000 字节 SQL。原始 statement 对象在 batch 前解包交给 binding；没有改写 SQL 或产品事务。

累计已确认读取超过 100,000 行或写入超过 10,000 行后，拒绝后续操作。这是**返回后观察阈值，不是精确费用硬上限**：已发出的查询无法靠计数器撤销；`first`/`raw` 没有行计量元数据，失败调用也可能实际执行。回执分别记录缺少行元数据的调用数和原生 Promise 拒绝数，不把它们当零费用。控制记录的正常路径另有三条 SQL，不计入用例的 200 条限额。

本地完整成功路径各用例 SQL 条数（不含三条控制 SQL）：13、117、117、112、27、116、116、28、28、122；顺序与 `BYOK_D1_CASES` 一致。最重用例合计 125 条。当前 [D1 限制](https://developers.cloudflare.com/d1/platform/limits/)为每次 Worker 调用 Paid 1000 / Free 50 条查询，因此此版本不能直接用于免费档。后续预检须确认现有套餐足够；不得自动升级或新增订阅。

20 秒是新调用准入窗口，不是整个用例或数据库执行硬超时。按照 [Workers 生命周期文档](https://developers.cloudflare.com/workers/runtime-apis/context/)，`waitUntil` 在断连/响应结束后最多延长 30 秒；超时或 host 退出仍可能留下 PENDING。不得将应用没有重试解释为平台内部绝无重试，也不得把收尾计数解释为原生查询取消 ACK。

处理器仍依赖外层 Access、固定 D1 绑定身份、基线/费用预检及唯一执行目录；仅检查 URL 和控制行不能证明部署隔离。尚未补齐全 56 表实际归属与原子清理守卫、完整云端单次操作器、独立关闭/凭证回收、冻结 Worker 入口/配置及新的 Wrangler dry-run，**所以本轮没有上线入口**。
