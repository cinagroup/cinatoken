## Response and resource ownership

The v394 append callback uses the same dedicated holder transport as custody, send-start and invocation facts. It passes the actual SQL operation to the request lifetime owner; cancellation does not race an in-flight financial or observation write against a timer. The direct client validates the immutable observation receipt within its transaction and returns only after COMMIT and connection-close acknowledgement. Uncertainty is surfaced as a failed stream and never grants another physical send.

The observer reads one source stream, hashes its fetch-readable bytes and forwards those bytes without a second fetch or tee. JSON success requires a complete valid body and EOF; the entire bounded JSON body is withheld until the durable append acknowledges. SSE success requires coherent identity, terminal usage, `[DONE]` and EOF. It withholds the terminal event until the durable append acknowledges, so a client that stops reading at `[DONE]` has not outrun the database record. An observation confirms complete upstream consumption; it does not assert complete downstream delivery, Provider billing finality or permission to charge a buyer.

The accepted response is bounded to 1 MiB JSON or 16 MiB SSE, with a 64 KiB event/tail bound, at most 16,384 events and bounded JSON depth/nodes. JSON buffering uses a fixed byte array, so one-byte source chunks cannot create an unbounded list of retained chunk objects. Invalid UTF-8, duplicate decoded keys, conflicting identity/usage, truncation and missing terminal markers fail closed. These limits narrow the accepted upstream response contract and do not imply support for every OpenAI-compatible provider extension.

Normalized usage includes nullable cache, reasoning, audio, image, text and prediction details, plus the reported service tier. This preserves fields present in the official [Chat Completions response contract](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create); values remain observations. The existing v360 quote accepts a flat text request subset, and no new supplier-bill or settlement authority is created by this entry.
