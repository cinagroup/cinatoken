# C04 prepared text grant and physical egress contract (v361 review)

2026-09-25. The [local TypeScript contract](../../../../packages/proxy/src/services/chat-text-grant-egress-contract-v361.ts) is unused and default off. It specifies what a future independently authorized broker and secret holder must prove for the platform-credential, flat-text Chat subset covered by the [v360 manifest](./C04-authenticated-complete-text-quote-v360.md). It is not a grant issuer or an independent secret holder.

## Exact claim and acknowledgement

The Worker proposes the tuple `(request_id, quote_id, final_body_sha256, candidate_index, model_id, route_target_id, provider_id, endpoint_id, credential_class=platform, credential_id=provider_id, provider_ciphertext_sha256, prepared_route_source_sha256, POST, upstream_url_sha256, outbound_body_sha256, outbound_body_canonical_sha256, outbound_body_bytes, credential_fingerprint_sha256)`. The URL and plaintext secret do not enter the claim; only digests do. The prepared identity comes from the same frozen body, URL, and headers used by the text driver's `fetch`. The canonical body digest describes the JSON value in that frozen upload snapshot; the raw body digest describes its encoded upload bytes. For v360's supported class the prepared credential must be exactly one bearer header. The Worker rejects a changed route, wrong candidate or endpoint, BYOK/shared-key source, or missing prepared identity before calling the broker. The platform `providerKeyId` check now matches the real route mapper's `providerKeyId=providerId` shape. The production repository decorator decrypts Provider keys before that mapper, so this review-only gate's `enc:v2:` requirement still rejects a real Chat route. A separate credential-opaque routing/holder path is required.

An acceptable broker response echoes that exact tuple and includes an acknowledged committed grant ID, attempt number 1–3, unexpired deadline no later than the parent quote, matching manifest/current route-source generation and attestation digests, and the manifest source digest. The local gate enters a one-shot state **before** awaiting the broker. Denial, malformed response, lost COMMIT/connection-close acknowledgement, expiry, abort, or concurrent reentry calls no sender. A later physical send is forbidden from reusing this request-local gate after any result. The [gate tests](../../../../packages/proxy/src/services/chat-text-grant-egress-contract-v361.test.ts) passed 5/5, including 22 altered receipt fields, route mutations, unknown acknowledgement, concurrent reentry, and a counterexample showing that a same-Worker echo accepts an unrelated plaintext bearer. The combined quote/admission/gate/wire suite passed 24/24 and Proxy typecheck passed.

## Required broker facts still absent

The broker must derive the manifest row from the committed v360 quote and match the candidate, target, credential class/id, provider ciphertext hash, and stored source generation. In the same transaction it must verify the **current** route and credential revision, active Key/User/Workspace, all ordinary and Guardrail reservations and their lease/capacity coverage, and the DB-derived complete three-attempt ceiling. It must consume one durable grant number no greater than three using a server-clock deadline before returning a committed acknowledgement. A new target after quote commit has no manifest row and must be denied. A Worker-supplied boolean or echoed fields cannot substitute for these DB reads and locks. The existing v350/v351 admission APIs accept caller amounts and do not bind a v360 manifest or physical attempt.

The v360 parent response does not expose manifest rows, and its `provider_ciphertext_sha256` hashes encrypted storage bytes. The prepared `credential_fingerprint_sha256` hashes the plaintext value placed on the wire. Their equality is neither expected nor meaningful. An independently controlled secret holder must fetch the credential itself, verify the ciphertext source/revision and grant, then prepare and check the actual plaintext wire credential, URL, method and body immediately before its own fetch. The holder must reject any later URL/body/secret substitution, expiry after acknowledgement, ambiguous grant outcome, second send, or hidden retry. The current text callback and this gate execute in the same Worker, so they do not establish that independent boundary.

The v360 `final_body_sha256` need not equal `outbound_body_sha256`: the driver replaces the public model with a provider model and may inject supported defaults or stream controls. The [v362 local wire check](./C04-flat-text-wire-transform-v362.md) recomputes the supported public-body-to-upload JSON transformation from the exact final quote bytes and compares its canonical digest, resolved URL hash and encoded length with the prepared attempt. Its real-driver tests stop before `fetch` and reject altered messages or forged URL/length fields. The check cannot independently rederive the raw upload hash from canonical final-body bytes, whose original object insertion order is lost; a deliberate forged raw hash passes. The future independent holder must repeat the semantic check against the committed quote, hash its own exact upload bytes, and verify its own secret before sending. The local tests do not prove durable reservation, DB revocation races, physical secret custody, a physical send, or billing reconciliation. C04.1–8/G therefore remain open.
