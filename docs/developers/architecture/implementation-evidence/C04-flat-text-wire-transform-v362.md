# C04 flat-text Chat quote-to-upload transformation (v362 local review)

2026-09-25. The [v362 wire check](../../../../packages/proxy/src/services/chat-flat-text-wire-proof-v362.ts) is an unused, same-Worker consistency check in the [review-only text grant gate](../../../../packages/proxy/src/services/chat-text-grant-egress-contract-v361.ts). It does not issue a database grant, control an independent credential holder, or authorize a physical send.

## What the local check binds

The [final quote input](../../../../packages/proxy/src/services/chat-final-quote-input.ts) contains exact UTF-8 public-body bytes and their SHA-256 digest. The check rehashes those bytes against the v360 quote, verifies its ordered model list and selected candidate, parses only the v360-supported Chat body keys, and requires the direct OpenAI Chat passthrough route without `customParams`. It resolves the selected route's OpenAI URL and applies the same body steps as the [OpenAI driver](../../../../packages/proxy/src/services/egress/openai-driver.ts): remove the public `models` control, merge route defaults, replace `model` with the provider model (including any Vertex prefix), and add `stream_options.include_usage=true` for a stream. A canonical JSON SHA-256 of that expected body must equal `outboundBodyCanonicalSha256` from the driver's prepared attempt.

The driver obtains that canonical digest from the [frozen JSON upload projection](../../../../packages/proxy/src/services/egress/owned-json-upload-body.ts) used by its request-owned encoder. The [prepared attempt](../../../../packages/proxy/src/services/egress/prepared-text-attempt.ts) separately carries the SHA-256 and length of the encoded upload, plus URL and effective bearer fingerprints. The check also recomputes the resolved URL SHA-256 and the expected encoded content length and compares both with the prepared attempt. The gate requires the canonical field before asking for a grant and includes it in the proposed claim and required receipt echo. The v360 public-body hash and encoded upload hash can differ because the selected provider model and stream controls change the body.

The check does **not** independently derive `outboundBodySha256` from the canonical final-body bytes. Canonical JSON preserves the value but loses the original object insertion order, so reconstructing the expected body can produce different encoded bytes. The real driver hashes its own frozen projection; this Worker-side proof treats that raw hash as a claim field. An independent holder must hash its own upload bytes before sending and verify that value against the committed grant. A deliberately forged raw hash passes the local transformation check, demonstrating this limit.

The [real-driver tests](../../../../packages/proxy/src/services/chat-flat-text-wire-proof-v362.test.ts) stop in `beforeFetch` after upload preparation. They pass the second fallback model with stream usage injection, reject altered message content and forged URL/length fields, and demonstrate acceptance of a forged raw hash by this local check. The [gate tests](../../../../packages/proxy/src/services/chat-text-grant-egress-contract-v361.test.ts) cover claim/receipt echo, rejection and one-shot ordering. The gate's platform route check was corrected to require `providerKeyId=providerId`, matching the [live route mapper](../../../../packages/proxy/src/services/model-router.ts), instead of rejecting normal platform routes with a non-null key ID. A second live-route mismatch remains: the [Worker repository decorator](../../../../packages/proxy/src/runtime/workers.ts) decrypts `enc:v2:` Provider keys before routing, but the local grant claim requires the stored ciphertext hash. Thus the current real Chat route fails closed at this gate even with the ID fix; the separate holder must obtain the ciphertext source and secret under its own authority. On this worktree, `npm run test:complete-chat-quote -w @octafuse/proxy` passed **24/24** (including **4/4** real-driver wire tests), and Proxy typecheck passed. The separate text-stream suite passed **190/190** in the same local continuation.

## Boundary still required

All of these values and the `send` callback remain inside one Worker. The gate tests deliberately demonstrate that a same-Worker broker echo accepts a bearer unrelated to the quoted ciphertext. An independent holder must load the committed quote and current manifest/source facts through its own authority, obtain the provider secret itself, recompute the quote-to-upload transformation and exact wire commitments from its own prepared request, and check the committed, unexpired one-shot grant immediately before its own `fetch`. A lost COMMIT or connection-close acknowledgement cannot become permission to send or retry. The durable attempt/unknown-result protocol, lease renewal for long streams, provider-bill reconciliation, and buyer/seller economic outbox are still outstanding. No physical egress, formal migration, remote SQL, or deployment occurred for this check; C04.1–8/G remain unchecked.
