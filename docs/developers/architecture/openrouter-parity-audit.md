# OpenRouter 功能对照审计（2026-08-31）

本文审计 cinatoken 当前仓库中的公开产品、协议和控制面能力，并以 OpenRouter 的公开文档为对照。状态只代表代码与本地测试证据，不等同于已经部署、完成远端数据库迁移或通过真实 Provider 凭据验收；也不表示复制 OpenRouter 的品牌、专有内容或内部实现。

状态口径：

- **已实现（本地）**：主路径、拒绝路径和存储契约在当前仓库中存在，并有相应测试证据。
- **部分实现**：存在可用核心，但公开 DTO、权限范围、兼容语义、管理面或生产验证仍不完整。
- **未实现**：不能用相似命名、管理员内部能力或预算账本替代 OpenRouter 对外产品契约。
- **发布门禁**：本矩阵只把有 focused test 或存储合同证据的主路径标为本地实现；每个发布候选仍必须重新记录 Core/Proxy/Admin 全量测试、类型检查、Workers bundle、三库迁移合同和安全复核的实际结果。本文不声称本轮所有门禁已经通过，也不替代远端迁移、Workers 部署、真实账号/Provider 故障注入和生产权限验收。

官方基线入口为 OpenRouter 的[完整文档索引](https://openrouter.ai/docs/llms.txt)，重点包括 [Models API](https://openrouter.ai/docs/api/api-reference/models/list-all-models-and-their-properties)、[Provider Routing](https://openrouter.ai/docs/guides/routing/provider-selection)、[Model Fallbacks](https://openrouter.ai/docs/guides/routing/model-fallbacks)、[Errors and Debugging](https://openrouter.ai/docs/api_reference/errors-and-debugging)、[Endpoints API](https://openrouter.ai/docs/api/api-reference/endpoints/list-all-endpoints-for-a-model)、[ZDR Endpoints API](https://openrouter.ai/docs/api/api-reference/endpoints/preview-the-impact-of-zdr-on-the-available-endpoints)、[Workspaces](https://openrouter.ai/docs/guides/features/workspaces)、[Management API Keys](https://openrouter.ai/docs/guides/overview/auth/management-api-keys)、[BYOK](https://openrouter.ai/docs/guides/overview/auth/byok) 与 [OAuth PKCE](https://openrouter.ai/docs/guides/overview/auth/oauth)。截至 2026-08-30，该索引还明确覆盖公开 Datasets、TypeScript/Python/Go Client SDK、Agent SDK、Ori 和大量框架/Agent 集成；这些属于 P2/P3 平台生态，不能与核心网关 P0 混为一谈。

## 总体结论

cinatoken 已经具备可运行的多协议 API Gateway、基础目录与门户、管理员 Provider/Model/Route 发布闭环、模型 fallback、Provider 偏好、跨模型全局 endpoint 调度、预算 reservation/settlement、Workspace 身份边界、四档 Workspace shared budgets、版本化 Preset/Guardrail 和严格的 route-level ZDR enforcement。本轮还完成了独立 `model_endpoints` 证据模型、管理员发布与 Route 绑定、Route+Provider subject 校验、SDK-shaped 的文本/Image/ZDR endpoint discovery，并把 selector、region、quantization、supported parameters、output capacity、Image `n/stream`、文本/Embedding，以及可证明的 Image 按张/参考图和 Audio 按时长/Unicode 字符价格预检与结算切换到同一个 verified Endpoint snapshot。匿名 `/api/v1/models` 与 `/api/v1/providers` 已形成 OpenRouter-shaped 公开目录合同，模型目录具备有界筛选、分页和 Workers Cache API 安全缓存；生产旧数据的 manifest-driven backfill/reverify 也已从只读规划推进到 PostgreSQL/MySQL 受审计 apply 的本地实现。与 OpenRouter 的主要差距已经不是“有没有中转”，而是完成生产迁移、真实数据认证写入与对账、公开协议的剩余精确一致性、尚未支持的多媒体计量维度、完整用户/Workspace 管理面、商业账户体系和平台生态。OpenRouter 当前官方索引还包含 Workspace members/CRUD、Management BYOK/Guardrail/Observability API、Files/Video、丰富的 Server Tools、API versioning/changelog 及三语言 SDK；这些不能由相邻的内部能力代替。

当前不能宣称 OpenRouter 等价。Chat/Responses/Messages 的基础流终态与取消、规范 Image 根路径与增量 SSE、STT JSON `input_audio`、verified Endpoint 运行时门禁，以及有权威证据时的文本/Image/ZDR endpoint discovery 已在本地收口；Image 的按张/参考图/条件请求费和 HTTP/DashScope 可证明的 Audio 时长或 Unicode 字符计费也已切换。Endpoint backfill/reverify 已具备三库 manifest-driven 只读 dry-run；PostgreSQL/MySQL 另有 trust-registry 多签、数据库持久 identity、serializable replan/CAS、追加式 run/evidence ledger、幂等与报告恢复的本地 apply 实现，D1 apply 继续 fail closed。独立、hash-only 的 Management principal、`/api/v1/keys` 管理子集以及 per-Gateway-Key lifetime/daily/weekly/monthly 消费上限已在本地实现，但尚未扩展到其它 Management 资源。远端 ledger/Management Key/Key-limit migration、一次性 trust-root bootstrap、生产旧数据 apply/对账和真实 Provider canary 都尚未执行。其余高优先级缺口包括 Image token/megapixel/variant 与 Audio token 等未支持计量、Realtime TTS 可证明字符事实、多媒体 `max_price`/price sort、真实性能/uptime 指标、全协议 usage/headers/ID/trace 精确一致性、TTS/音频合同、Management API 扩展、Workspace 公共管理和继承、私有 BYOK、Credits/支付/发票，以及真实生产验证。Native Gemini 与 DashScope Realtime 的继续加固属于 CinaToken 自有兼容目标，不计作 OpenRouter parity 缺口。公开 Models/Providers/文本 endpoint DTO 已有本地 focused coverage，但用户个性化过滤、完整上游字段、鉴权语义、真实指标和生产证据仍不等价；Generation 查询仍只是安全子集。

## 关键边界与不得误报项

1. `region` 是 Provider endpoint 位置发现，不是数据驻留。没有区域化入口、路由、日志/数据库边界和合规证据时，不得使用“EU/US residency”措辞。
2. ZDR 当前是强本地筛选与 fail-closed enforcement，并已有鉴权后的 SDK-shaped endpoint 预览；但当时的 OpenRouter live 预览可匿名读取，且 Workspace 继承、BYOK/shared-key 证据、工具策略与真实 endpoint 运行指标尚缺，只能标记为产品 parity 部分。
3. Presets 与 Guardrails 的本地核心已经进入 Workspace scope；缺的是公开管理、组织角色、继承/预览和生产验收，不能继续写成“尚未迁移”，也不能写成“OpenRouter 全量完成”。
4. `sort.partition="none"` 已经实现全局 endpoint 调度，不再列为功能缺口；剩余是生产故障注入和 trace 验收。
5. 安全聚合的 `endpoint_slugs`/`regions`、endpoint-level 文本/Image/ZDR DTO 和文本 endpoint 的 `status: 0` 已实现；真实性能指标仍保持 `null`。匿名 canonical `/api/v1/models/{author}/{slug}/endpoints` 与继续鉴权的历史 `/v1/*`、Image/ZDR discovery 是有意分开的合同。OpenRouter 两份 API reference 展示 management-key-only 的 403，但截至 2026-08-30 对应 live endpoint 曾可匿名读取，必须继续显式保留上游文档/live 冲突，并在发布前重验；限制更多或更少都不自动构成兼容。
6. 文本与 Embedding 已使用 Endpoint `pricing.request` 及 token/cache 价格执行 `max_price`、预算和结算，阶梯价格继续按最坏档上限比较；Image 按张/参考图与 Audio 按时长/Unicode 字符虽已使用 Endpoint 结算，但多媒体仍会对 `max_price` 和 price sort 安全拒绝。安全拒绝是正确边界，不是完整 parity。
7. `/v1/models` 的 `owned_by` 已使用 `cinatoken`；旧文档或响应示例中的历史品牌值必须在发布前清理。
8. 当前结论不代表已部署。本文只引用对应实现和 focused tests，不声称本轮相关全量回归、类型检查、Workers bundle 或三库迁移合同已经全部执行成功；这些结果必须在具体发布候选中记录。unknown outcome 后禁止重放、候选级有界 trace 和错误体上限已有本地覆盖，但仍须由真实上游故障注入复核。三库远端迁移、Workers 部署、真实 Provider 冒烟及生产权限验收仍属于发布门禁。

11. Endpoint subject fingerprint 已绑定当前 Route + Provider API 主体；运行时与 discovery 会拒绝 `providers.endpoints`、`api_key`、`shared_channel_type` 或 Route 合同漂移。但配置变化尚不会事务化主动 demote Endpoint 或写统一 drift audit；生产旧数据仍需显式 reverify，不能把读时拒绝或报告中的 proposed actions 误报成完整生命周期治理。

15. Manifest-driven plan 仍是只读双读，`validation_passed=true` 不构成授权；其 operator-supplied fingerprint 对比、`database_identity_verified=false` 和 `snapshot_consistent=false` 必须保留。独立的 PostgreSQL/MySQL apply 已用 DB-persisted identity、一次性 signer trust-root、strict registry-derived actor/reviewer/approver 多签、execution/request/trust digest、serializable fresh replan、数据库时钟、精确 CAS 和 immutable run/evidence ledger补齐本地写入安全边界；D1 apply 继续拒绝。`ENDPOINT_BACKFILL_APPROVAL_KEY_REGISTRY` 的 principal 是离线 trust registry 映射，不能误报为每次都在线查询 CinaAuth session。生产 migration/bootstrap、signer 生命周期与最小权限验收、旧数据 apply/对账、exit `7` 恢复演练和真实 Provider live canary 尚未执行，本轮没有运行生产迁移或部署。

## 生产连接门禁（历史发现，仍须远端复验）

此前生产审计曾观察到：`api.cinatoken.com/catalog/*` 从公网可返回合法空集合，但 `cinatoken.com` 的服务端渲染经公网域名读取时得到 401，导致模型、供应商、对比、Chat、排行和基准全部显示“不可用”。根因边界是控制面 Worker 到数据面 Worker 的调用路径，而不是页面组件缺失。以下是必须保留的修复契约，不表示本轮已经重新部署或完成远端验证。

修复契约：

1. Cloudflare 使用 Service Binding，避免从 Admin Worker 回源自身账户的自定义域名。
2. 当前代码在 Service Binding 缺失时会回退经过协议校验的 `CINATOKEN_PUBLIC_API_ORIGIN`；生产部署必须验证 binding 实际存在，后续宜把公网回退收紧为本地/自托管显式 opt-in。
3. Chat BFF 直接透传 `Response.body`，只保留安全响应头，避免大响应重复缓冲。
4. 数据库没有活动路由时返回 `ready + []`；页面明确提示管理员完成 Provider、Model、Route 三步发布，而不是显示故障。
5. 不使用模拟模型或伪造排行填充空库。

## 已建平台核心的生产实现契约（非优先级 P2）

以下契约是 P2 的实施与发布门禁。Gateway Key 已完成 Workspace 归属和普通成员本人管理；Preset、Guardrail 与共享预算的本地数据、查询和运行时核心也已 Workspace 化，并继续叠加 CinaAuth 用户、Gateway Key 和管理员权限。组织角色治理、完整公开管理 API、继承/预览、BYOK、Routing 和 Observability 尚未闭环，因此不得把整个平台误报为已具备 OpenRouter 对等的组织隔离。

### P2-A Presets

1. 数据模型使用不可变版本：`request_presets` 保存 Workspace 内唯一 slug、Workspace、所有者、`private | public` 可见性、状态及指定版本；`request_preset_versions` 保存递增版本、系统提示词和经过白名单校验的 JSON 配置。删除采用归档，历史版本不被原地覆盖。
2. slug 在 Workspace 内唯一且规范化，`@preset/slug` 只能在请求当前 Workspace 中解析。普通用户只能读取同 Workspace 中自己的私有 Preset 或可见的公开 Preset，只能写自己有权管理的 Preset；管理员可按 Workspace 治理资源、调整可见性、归档和指定历史版本。跨 Workspace 查找或回退均应 fail closed。
3. 代理支持 OpenRouter 的三种引用：`model: "@preset/slug"`、顶层 `preset: "slug"`、`model: "model-id@preset/slug"`。请求字段按浅合并覆盖 Preset；`tools` 按工具身份合并，保留 Preset 顺序并让请求同名定义覆盖。
4. Chat、Messages、Responses 分别把 Preset 系统提示映射为 system message、顶层 `system`、`instructions`；请求已经显式提供时以请求为准。`messages`、`input`、`prompt`、`stream` 等瞬态字段绝不持久化。
5. 提供用户门户 CRUD、版本列表/回滚、可见性与归档界面；提供管理员全局治理界面。另提供 `POST /api/v1/presets/{slug}/{chat/completions|messages|responses}` 的“保存配置并执行”兼容入口；已有 slug 新增并指定版本，新 slug 创建资源。
6. 配置采用字段白名单、大小/深度/数组上限和禁止键检查；不存在、无权限、已归档、无指定版本、非法引用、合并后缺少模型均返回稳定 4xx，不回退成普通模型名，也不把 Preset 原文写入请求日志。
7. 三种数据库迁移必须具备唯一键、查询索引和外键/约束；仓储契约覆盖 D1、PostgreSQL、MySQL。单元测试覆盖引用解析、访问控制、版本并发、三协议提示词、tools 合并、瞬态字段剥离和错误语义。

### P2-B Guardrails

1. Guardrail 是有 Workspace 归属的可版本化策略资源，可绑定同一 Workspace 内的用户和 Gateway Key；同一层只允许一个直接绑定。有效策略由用户层与 Key 层合成，模型/Provider allowlist 取交集，内容过滤器取并集且 `block` 高于 `redact`，预算分别独立检查，ZDR 按模型组取 OR，确保更严格规则胜出；跨 Workspace 绑定或解析必须 fail closed。
2. 首版覆盖模型 allowlist、Provider allowlist、自定义输入正则 `block | redact`、日/周/月预算、按模型组 ZDR。当前已拒绝 lookaround、反向引用和明显嵌套量词，并限制模式长度、数量和输入扫描字节数；尚缺总执行 deadline，扩展正则能力前必须补齐。
3. preflight 在模型/路由规划和任何上游调用之前执行；redact 后的正文只进入上游，不进入普通日志。postflight 仅在能够安全、完整缓冲的非流式输出启用；流式输出策略若要求阻断必须在请求前显式拒绝，不能边泄露边检查。
4. 规则命中返回稳定 403 错误码和最小必要元数据；服务端审计记录 guardrail/version/scope/action、命中规则的不可逆指纹和关联请求，不记录原始敏感文本。管理员已有 CRUD、版本和绑定界面；有效策略与符合条件模型/Provider 的预览 API/UI 尚缺。
5. 预算累计与既有 Key/用户预算并存，各自独立、最低可用额度生效；扣费路径必须幂等并覆盖并发测试。

### P2-C Provider 数据策略与 ZDR

1. 数据策略建模在具体 Provider endpoint/route target，而不是只挂在 Provider 品牌上；字段至少包含 retention、training、ZDR、证据 URL、核验人、核验时间、有效期和状态 `verified | expired | unknown`。
2. `unknown`、过期或缺少证据一律按“会保留且会训练”处理。只有管理员可发布核验状态；每次变更写审计历史，不允许普通用户声明上游合规。
3. 每次核验都必须绑定当前 Route + Provider trust subject 的版本化 SHA-256；subject 覆盖实际 endpoint、上游账号摘要、模型、协议/operation、adapter 与 `custom_params`。运行时重算不一致、旧记录无 fingerprint 或管理端配置变更后均立即 fail closed，并记录失效原因与审计事件。
4. 请求级 `provider.zdr: true` 只能收紧，不能覆盖用户/Guardrail 的强制 ZDR；按 Anthropic、OpenAI、Google、xAI、Other 模型组与有效 Guardrail 做 OR 合并。筛选发生在 route plan 阶段，候选为空时返回可解释 4xx，绝不静默降级到不合规 endpoint。
5. 工具与插件不继承推理 Provider 的 ZDR 保证。启用第三方工具而同时要求 ZDR 时，若工具没有独立且已验证的数据策略，必须拒绝或要求调用方显式关闭工具。
6. shared key 在策略过滤之后才注入，无法继承 route 默认账号的证据；在逐 shared key 证据模型完成前，ZDR 与 no-collection 请求一律排除共享渠道路由。公开目录与 endpoint API 只暴露 subject 仍匹配且可安全声明的字段，不暴露合同、凭据、fingerprint 或内部备注；per-model 与 `/endpoints/zdr` 已从 verified endpoint 证据返回 pricing/cache/tool-choice/voice，真实性能指标仍为空，且 OpenRouter 的 management-key/匿名权限语义仍未兼容。管理员界面提供 endpoint 与策略治理，受影响模型/endpoint 的统一有效策略预览仍需补齐。

### P2-B/P2-C 实现审计结果

- `0036_guardrails.sql`、`0037_route_data_policies.sql` 与 subject 绑定迁移 `0046` 已覆盖 D1；PostgreSQL 对应 `0036`、`0037`、`0045`，MySQL 对应 `0032`、`0033`、`0042`。三套仓储均实现同一接口，D1→PostgreSQL ETL 保持主表、版本、绑定、策略和审计的依赖顺序。
- Guardrail 在 Preset 合并后、路由规划前执行；模型/Provider 限制和 ZDR 因而作用于最终候选。非流式输出在返回客户端前过滤；配置输出过滤的流式请求直接拒绝，避免先泄露后阻断。
- 管理员创建的 scope 绑定不可被普通用户覆盖或删除；存在管理员绑定时策略资源对所有者只读，避免通过新版本、回滚或归档绕过强制策略。
- `provider.zdr: true` 只接受 subject fingerprint 与当前配置精确匹配、有效期内、有公开 HTTPS 证据、`retention_days = 0`、`training_allowed = false` 且明确支持 ZDR 的 route target。配置漂移、未知、缺证据、过期策略均 fail closed；携带第三方 tools 的 ZDR 请求返回稳定 400。
- 审计只记录规则/策略标识、动作、不可逆指纹、关联 request log 和策略快照，不记录命中的原始提示词或输出。

### P2 发布门禁

每个子阶段依次通过：数据库迁移契约测试 → 仓储/服务单元测试 → Proxy 与 Admin 全量测试和类型检查 → Workers bundle 校验 → 本地 Node 与 Workers preview 冒烟 → 权限与错误路径浏览器验收。任何迁移或运行时只完成一半时都不得部署；部署后再执行远端 D1 迁移、真实账号最小冒烟与回滚验证。
