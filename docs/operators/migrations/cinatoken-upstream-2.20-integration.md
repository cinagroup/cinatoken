# CinaToken 上游 2.20 合并迁移

此合并保留 CinaToken 的 CinaAuth、工作区、预算预留、钱包与财务审计。上游迁移追加为 `0086`–`0094`；已发布的迁移文件保持原样。Postgres 原有迁移截至 `0085`，D1 截至 `0081`，MySQL 截至 `0079`。后两种引擎编号中的空档是有意保留的。

| 上游编号 | CinaToken 编号 | 内容 |
| --- | --- | --- |
| 0031 | 0086 | 增加目录运营备注 `note`，保留 `description` |
| 0032 | 0087 | 按模型家族拆分 DashScope 音频适配器 |
| 0033 | 0088 | 请求日志供应商索引 |
| 0034 | 0089 | 粘性绑定关联键 |
| 0035 | 0090 | OAuth 访问令牌及请求日志归属 |
| 0036 | 0091 | OAuth 应用、客户端及临时授权请求 |
| 0037 | 0092 | OAuth 客户端凭据 |
| 0038 | 0093 | 供应商默认请求参数 |
| CinaToken 整合 | 0094 | 扩展工具审计约束以接受 DeepSeek，保留原有审计记录 |

升级前核对目标数据库、分支、角色与最新可恢复备份。在迁移演练中验证现有管理员会话、工作区授权、周期余额、钱包余额、预留与历史财务记录。预览 `0087` 将改动的路由；适配器属于端点验证的主题，发生变化的路由需要重新核验相应定价与数据政策。

先用既定迁移角色应用迁移并检查记录，再部署代理与管理后台。Cloudflare 发布工作流本身不执行 Postgres 迁移。迁移必须使用事务、固定迁移清单、角色与数据库校验、互斥锁和有上限的语句等待。重复执行迁移器应跳过已记录迁移，不能直接重复执行迁移 SQL。

新旧管理接口都接受 `description` 或 `note`；同时提供且不同会拒绝写入。新写入同步两列。旧服务并行运行期间，以存在的 `description` 列为准，包括显式清空，避免旧写入被过时镜像覆盖。运营备注不作为公开目录文案。

OAuth MCP 调用先校验令牌，再使用服务端解析的、绑定个人默认工作区的内部 Gateway Key，继续经过现有预算与 Guardrail 结算路径。请求日志同时记录该 Key 与 OAuth 令牌 ID。内部 Key 被撤销后不得重新创建；令牌不能用于模型推理接口。

回滚应用时保留新增列、OAuth 归属与财务审计数据；不要自动回滚数据库。新增适配器配置需要随应用能力一起评估。已有登录故障的修复依赖 Postgres `0082`–`0085`，回滚不得删除这些迁移。

D1 到 Postgres 的 ETL 继续要求目标离线及源端冻结确认。当前 CinaToken 命令不支持上游分阶段示例中的 `--kind`、`--prune`、`--since`，传入会明确报错；不能把这些示例当作本部署的执行命令。OAuth 应用、客户端、令牌及 MCP 配置已加入表注册表；短期会话、一次性授权请求不迁移。不要对在线生产库执行清空或切换操作。

供应商的协议默认参数进入端点与数据政策的信任主题；非空默认参数变化后必须重新验证端点及数据政策。数据政策条件写入同时比较供应商原始默认参数，防止审核期间的并发修改。未配置默认参数的旧主题指纹保持兼容。

流式首字节保护保留 CinaToken 的既有语义：默认关闭，配置为空时仅作用于默认路由组，心跳数据块可满足首字节保护。最后候选也遵守请求的绝对期限。Gemini 签名兼容工具保留，但签名拒绝不会触发驱动内部隐式重发；再次请求必须重新经过预算准入与报价校验。DashScope 实时 TTS 在无法证明操作级 Unicode 码点上限时继续拒绝转发。

恢复原型仍保持关闭。由于正式 D1 迁移清单追加到 0094，本轮更新本地模式校验清单的迁移数量与源文件摘要；四张恢复表的对象定义摘要、提案 SQL 和启用边界保持不变，测试继续逐项比较全部 24 个对象。
