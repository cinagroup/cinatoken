# AGENTS.md — `@octafuse/admin` (cinatoken)

## Overview

Gateway **Admin** console: API keys, providers, models, routes, `system_config`, request logs, budget audit, analytics. Stack: **Next.js 16 + OpenNext on Cloudflare**.

This package lives in the **`cinatoken`** monorepo and **binds to D1** via `wrangler.jsonc` (`DB`). Public admin HTTP APIs are **`/api/admin/*`** (internal Hono uses **`/admin/*`**). The **`@octafuse/proxy` Worker does not expose admin routes**.

**Out of scope for this app**: desktop client version feeds, plugin catalogs, user-growth analytics in a separate billing/portal product—the Admin here is **gateway operations only**.

## Commands

**Prefer repo root** (reads root `.env` / `.env.local`, same convention as Proxy Node+PG):

```bash
npm run dev:admin        # OpenNext preview + D1 :8789
npm run dev:admin:node   # Next + Postgres :8789 (DATABASE_URL, DATABASE_DRIVER same rules as Proxy Node + ADMIN_USERNAME / ADMIN_PASSWORD)
```

Inside **`packages/admin`** (needs `.env` here or `ln -s ../../.env .env`):

```bash
npm run dev           # :3000, no D1 (admin API returns 500; UI-only edits)
npm run dev:node      # :8789 + Postgres (same port as preview)
npm run build:cf      # OpenNext output + worker.js
npm run preview       # :8789 + D1 (--persist-to ../../.wrangler/state)
npm run deploy        # Deploy to Cloudflare
npm run cf-typegen    # Regenerate cloudflare-env.d.ts (required after fresh clone; file is gitignored)
```

For full admin API debugging use **`npm run preview`** or root **`npm run dev:admin`** (D1), or **`npm run dev:node`** / **`npm run dev:admin:node`** (Postgres). Do not rely on Proxy Worker alone.

After a remote deploy (`deploy:*` / `db:migrate:remote`) on this machine, run **`npm run gen:wrangler`** before local D1 dev so Admin/Proxy/migrate share the same local SQLite identity — see [local-development.md §1](../../docs/developers/local-development.md#️-本地-d1-与-database_id远程-deploy-后必读).

**Self-hosted Postgres + containers**: **`Dockerfile.admin`** multi-stage build runs **`npm run build:docker`**（Next standalone，**不**跑 `wrangler types`，与 CI 中 `npm ci --ignore-scripts` 兼容；类型兜底见 **`types/cloudflare-env-shim.d.ts`**），默认 **`CMD`**: `node packages/admin/server.js`，`:8789`，应用进程 only。Schema changes use the **`Dockerfile.migrate`** image (`docker compose --profile migrate run --rm migrate`). Inject **`DATABASE_URL`**, **`DATABASE_DRIVER`** (default `postgres` if omitted), and **`ADMIN_USERNAME` / `ADMIN_PASSWORD`**, same database as **`Dockerfile.proxy`**. See `../../docs/operators/deployment/docker.md`.

## Architecture

| Path                                                                 | Role                                                                                        |
| -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| `app/api/admin/[...path]/route.ts`                                   | Database Session or named Admin API Key auth; rewrite URL → Hono                            |

| `lib/routes/admin/*`                                                 | Admin HTTP handlers                                                                         |
| `lib/services/admin/*`                                               | Admin services (use `@octafuse/core`)                                                       |

| ---------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ADMIN_USERNAME`                                           | Console login username; in **`wrangler.jsonc`** `vars` for Cloudflare (placeholder `admin` ok).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |

Local: **`packages/admin/.dev.vars`** (see `.dev.vars.example`; `npm run preview` / `dev:admin` auto-creates with **`admin` / `admin`** via `scripts/ensure-dev-vars.mjs` if missing). | `ADMIN_COOKIE_SECURE`                                      | Optional hardening. Unset by default (**no** `Secure` on `admin_session`, so plain HTTP works). Set `1`/`true`/`yes`/`on` only if Admin is already served over HTTPS and you want the browser to send the session cookie on HTTPS only — see [`docs/operators/deployment/docker.md`](../../docs/operators/deployment/docker.md) §7.3.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `CINATOKEN_ADMIN_CONFIG_REQUIRE_REVISION`                  | Default `false`. Exact `true` makes generic `PUT /api/admin/config` require a revision condition for the five Web-managed keys; deploy all new Admin instances and drain old writers before enabling, then enable the Web Config routes.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `CINATOKEN_ADMIN_KEYS_REQUIRE_REVISION`                    | Default `false`. Exact `true` requires client `expected_revision` for global Gateway Key PATCH/DELETE (missing → 428). Upgrade all Admin writers/clients before enabling; no schema migration is needed.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `CINATOKEN_ADMIN_MODELS_REQUIRE_ROUTE_POLICY_PRECONDITION` | Default `false`. Exact `true` requires explicit `expected_route_policy` on model PATCH that writes `route_policy` (missing → 428); always enforce provided raw nullable current-value read-set (stale/absent → 409). All new model columns and optional tags in that conditional request share the D1 batch / PG or MySQL transaction. No new schema; native locks/isolation/ACL remain acceptance gates. Deploy every new Admin instance, upgrade strict clients and drain all old unconditional writers before enabling this guard and then the independent Web entry. A→B→A matches current A; this is not a history/revision guarantee.                                                                                                                                                                                                                                                                                                                                                 |
| `CINATOKEN_ADMIN_DATA_POLICIES_REQUIRE_PRECONDITION`       | Default `false`. Exact true requires the two expected subject/current-policy hashes on Data Policies PUT (missing → 428); supplied pairs always validate. Web sends both safe hashes and the canonical expected Console subject. The server constructs authoritative raw route/provider/policy read-sets, and all three database writers atomically compare them and append audit; stale state → 409 with no partial write. This compares current values, so matching A→B→A is allowed. Upgrade every Admin writer/client and drain old unconditional instances before enabling this guard and then the independent Web entry. No new schema; native concurrency, UTC microseconds, audit rollback and platform acceptance remain required.                                                                                                                                                                                                                                                 |
| `CINATOKEN_ADMIN_TOOLS_REQUIRE_VERSION`                    | Default `false`. Exact `true` requires the complete family `tools_version` and operator reason for the eight generic Tools catalog/active config keys. Dedicated Tools save/reveal always require the version vector and, for Console, the verified subject header. First apply D1 0076/MySQL 0074/Postgres 0081, grant metadata-only audit SELECT/INSERT and the Postgres mutex SELECT/UPDATE(id), then upgrade clients and drain all old writers. Only then enable the guard and the independent Web Tools entry. Keep audit storage, mutex and compatible readers on rollback.                                                                                                                                                                                                                                                                                                                                                                                                           |
| `CINATOKEN_ADMIN_SHARED_KEYS_REQUIRE_REVISION`             | Default `false`. Exact `true` requires client `expected_revision`, operator reason and, for Console PATCH/DELETE, `X-CinaToken-Expected-Console-Subject` (missing → 428). The header is canonical `encodeURIComponent` of the verified raw Console subject; it must match the current trusted subject and never selects the actor. Whenever supplied, it is validated even with the guard off, including earnings review; earnings without it keeps legacy compatibility. First migrate D1 through 0075/MySQL through 0071/Postgres through 0080; upgrade audit readers for Console actor IDs up to 617 (raw subject, named API-key actor and reason remain 600), then drain old Admin writers and upgrade clients. Enable the API guard, then opt in the Web Shared Keys page. All new-server writes require atomic governance auditing even with this guard off. Keep widened audit storage and compatible readers on rollback. Long-subject login storage is a separate acceptance gate. |

| `HYPERDRIVE`                                               | Cloudflare Postgres binding; generated from `HYPERDRIVE_ID`, never from a committed connection string                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `DATABASE_DRIVER`                                          | Node: omit → `postgres`; Cloudflare: omit → D1, explicit `postgres` → `HYPERDRIVE`; invalid or missing companion binding/URL → **error**                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |

Downstream portals: set **`GATEWAY_MASTER_URL`** to this app’s origin, create a named least-privilege key in **Integration Keys**, then call **`/api/admin/...`** with `Authorization: Bearer <ADMIN_API_KEY>`.

**CinaAuth session capacity**: OIDC standard subjects are at most 255 ASCII characters; the stored `cinaauth:` prefix adds nine. Apply MySQL `0072_admin_session_username_oidc_capacity.sql` before accepting the full standard range, and preserve the widened `admin_sessions.username VARCHAR(264)` on rollback. D1/Postgres already use TEXT for this column. Keep the existing issuer/subject checks and other identity columns unchanged; the governance header's 600-character tolerance is not an issuer promise. Local callback/SQL wire contract tests do not prove native DDL or external IdP login. Audit actor limits in other Admin domains remain independent acceptance gates.

**Integration-key audit capacity**: `console:cinaauth:` adds 17 characters, so a standard subject255 requires actor272. Apply MySQL `0073_admin_access_key_actor_oidc_capacity.sql` before deploying the expanded Access Keys audit writer/reader, retaining `actor_id VARCHAR(272)` and the session264 column on rollback. D1/Postgres audit actors already use TEXT. Keep Console-only access and the existing control-character/code-point validation; do not truncate actors or silently skip malformed history. Reconcile the complete actor and microsecond timestamp in D1-to-PG ETL. Drain old writers and keep the Web entry disabled until the full database/identity/platform acceptance is complete; older writers still reject long actors and lack the new ignored-target/audit guarantees.

**Chain-operation rejection**: withdrawal and NFT management use the global Portal ledger with `users.read/write`. Process acknowledges Queue delivery only. New Web/shared Next writes fresh-check the same Console subject and send the canonical expected-subject header; supplied headers always validate, while header-less legacy clients retain existing authorization. Admin reject uses `rejectRequestedWithdrawal` for requested + null tx hash + no persisted outbox, preserving the wide chain-revert refund method. Apply and verify formal D1 0077/MySQL 0075, native triggers/permissions and old-writer drainage before release. MySQL outbox DDL does not enable MySQL Chain Worker. Keep both Web entry flags false until database/chain/identity/platform acceptance; keep ledger guards and compatible readers on asset rollback.

## Internationalization (i18n)

Admin UI uses **[next-intl](https://next-intl.dev)** in **without-i18n-routing** mode (no `middleware.ts`, URLs stay `/dashboard`, `/gateway/*`).

| Path                                   | Role                                                              |
| -------------------------------------- | ----------------------------------------------------------------- |
| `lib/i18n.ts`                          | Locales (`en`, `zh`, `ja`, `ko`), cookie-based `getRequestConfig` |
| `lib/locale.ts`                        | `LOCALE_COOKIE` (`NEXT_LOCALE`), `resolveLocale()`                |
| `app/api/locale/route.ts`              | `POST` sets locale cookie                                         |
| `components/layout/LocaleSwitcher.tsx` | Language dropdown (sidebar + login)                               |
| `messages/en.json`                     | English copy                                                      |
| `messages/zh.json`                     | 简体中文 copy                                                     |
| `messages/ja.json`                     | 日本語 copy                                                       |
| `messages/ko.json`                     | 한국어 copy                                                       |

**Conventions for new UI copy:**

- Add strings to all files under `messages/` with identical key structure, using `messages/en.json` as the structural baseline (`sidebar`, `providers`, `config`, `common`, …).
- Client components: `useTranslations('namespace')`; server layout/metadata: `getTranslations` from `next-intl/server`.
- Do **not** hardcode user-visible English in JSX or `lib/*` UI helpers — pass `t()` or a labels object (see `lib/pricing-ui.ts` `PricingLabels`, `getBusinessTimezoneOptions`, `getBillingCurrencyOptions`).
- **Out of scope**: Hono/service error messages (display `data.message` as-is), JSON presets (`provider-import-presets.json`, `model-presets/*`), provider/model IDs.
